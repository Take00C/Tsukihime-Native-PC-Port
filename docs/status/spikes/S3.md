# Spike S3: compositing at 1920 x 1080 (blend shaders, backdrop blits, rule wipe)

**Verdict: PASS.** The baseline (full-target backdrop blit before every blend quad) needs
0.68 ms GPU per frame at p99 and 0.74 ms at most over 600 frames. The threshold is 4 ms at p99
and 8 ms at most (ROADMAP M0 spike table; reading in `docs/status/spikes.md`). The fallback is
not needed. Every blend shader matches `tsuki.compose` within 1 UNORM8 level on the test
pattern. An aligned 13-layer frame with a rule wipe matches within 2 levels on 99.97 % of
pixels (T5 (b) needs 99.9 %), once the PS4's fp16 colour export is modelled (section 4.3).

Owner: stream D. Run on 2026-10-25, at commit `cd94425` plus the uncommitted M0 tree (dirty;
the spike is not committed yet). Release build, no debugger, nothing else heavy running.

## 1. What was built

`src/Spikes/S3.Blend1080/` (namespace `Tsuki.Spikes.S3`):

| file | content |
|---|---|
| `GlWindow.cs` | SDL3 window with a GL 3.3 core context (ppy.SDL3-CS); Silk.NET.OpenGL loaded through `SDL_GL_GetProcAddress` |
| `Shaders.cs` | One GLSL source compiled once per mode (`#define MODE n`). It covers PS #2 basic 2DTex, PS #3 basic 2D, PS #0 transition 2DTex and the 24 blend shaders of compositing 2.3, written from `compose.py`: dodge black rule 3/255 = `uintBitsToFloat(0x3C40C0C1u)`; the v_min / v_max NaN cases of dodge, burn and ps_dodge selected explicitly; soft light as `exp2(log2(d) * e)`; hard light on `C.rgb * S`; nexl and PS alpha families |
| `Effects.cs` | `compose.effect` (draw-mode word to shader mode, strength, blend state, P2), `rule_params` with a vague width, `fads_step`, `fads_vertex_alpha` |
| `Compositor.cs` | Quad executor. Shader is chosen from the word as SelectShader does. Before every backdrop-reading quad, `glBlitFramebuffer` copies the full target or the quad bounds into the backdrop texture; D is read with `texelFetch(gl_FragCoord)`. Then the 14 blend states of table 0x2D8030 are applied. Transitions: effect 56 fill and capture; rule pass (effect 58, state 4) then capture pass (effect 26, state 6); quantised cross-fade. RGBA8 targets, straight alpha, no sRGB |
| `Bench.cs` | Timed scene and per-frame statistics (`GL_TIME_ELAPSED`; optional `GL_TIMESTAMP` breakdown) |
| `Verify.cs` | Renders the test-pattern cases and the aligned check frame for the Python comparison, and compiles every shader as GLSL ES 3.00 |
| `tools/export_s3.py` | Python oracle export into `samples/spikes/s3/`: 13 logical pictures (`Pictures.script`, catalog) plus RULE_29 (allpac3 as stored), 283,073,100 bytes RGBA; the 256 x 256 pattern; the 419 cases; the check scene |
| `tools/verify_s3.py` | Computes the `tsuki.compose` references and writes `samples/spikes/s3/verify/report.json` and PNG previews (local only) |

Blend-state mapping. GL ignores the blend factors for `GL_MIN` / `GL_MAX`, while GCN applies
them (compositing 4.1). States 4 and 10 are therefore written as equivalent `ADD` forms:

- state 4: alpha = `sa*1 + da*0`;
- state 10: alpha = 0.

States 5 and 11 use `MIN` / `MAX` with factors ONE, where ignoring the factors changes
nothing. All 14 states match `compose.apply_blend_state` (section 4.2).

Pictures are one texture each, sampled without mipmaps (`GL_LINEAR` while timing, `GL_NEAREST`
for the check frame). ARCHITECTURE 4 plans one texture per tile; that adds draw calls but no
fill cost.

## 2. Scene that was timed

The frame is 1920 x 1080 RGBA8, drawn into an FBO and presented scaled into a 1280 x 720
window. Each frame draws, in order:

1. Clear.
2. Backdrop IMG2345, 2070 x 1230. It zooms every frame: zoom 1.0 to 1.25 about the frame
   centre, 240-frame period, word 0.
3. Ten layers in `_STBR` modes 11, 17, 19, 23, 24, 11, 17, 19, 23, 24, each with an affine
   transform:
   - scale: cover scale x (1.15 +- 0.05);
   - rotation: +-2 degrees;
   - drift: +-20 px;
   - every third layer mirrored.

   Each layer covers the frame. The pictures come from the opening montage (script 3,
   statements 93..127 and 1888..1896):

   | mode | pictures |
   |---|---|
   | 11 | IMG2230, IMG2232 |
   | 17 | IMG2183, IMG0813 |
   | 19 | IMG2439, IMG1685 |
   | 23 | IMG1685, IMG0597 |
   | 24 | IMG2182, IMG0597 |

4. Two partial-screen sprite layers:
   - IMG2163 in mode 13, scale -0.45 / 0.45, moving;
   - IMG0758 in mode 19, scale 0.9, rotating.
5. A continuous `_FADS(2, 1500, 29)`:
   - progress step = `compose.fads_step(1500)`;

The census variant (run D) uses the five most-used `_STBR` modes, 17, 11, 23, 24 and 22,

The pattern is 256 x 256: S (layer), D (backdrop) and R (rule).

- Rows 0..127 are a systematic grid: every S level against every second D level, per channel.
- Rows 128..255 are random, with about 6 % of the channels snapped to 0, 1, 2, 3, 4, 127,
  128, 254 or 255.

### 4.2 Why the differences are 1 level: the fp16 colour export

The GPU always rounds down near .5 when the shader output goes straight to the target (blend
state 0). Modelling the export as fp16 rounded toward zero (`v_cvt_pkrtz_f16_f32`) explains it:

- the state-0 cases drop from 6.4 % mismatching pixels (mean over 25 cases; 13.1 % in the worst
  case) to 0.001 % (0.005 % in the worst case);
- the rule mask becomes bit-exact.

So the AMD GL driver exports RGBA8 colour the way the PS4 shaders do (compositing 2.1: "MRT0 is
exported packed fp16 (compr, round toward zero)"). The remaining 1-level differences of the
blending states lie on rounding ties of the blender (fractions 0.45..0.52 of a level, both
directions). Models with fp16 blending, or with 8- to 12-bit fixed-point factors, fit worse. The
GPU is therefore closer to the PS4 export than `compose` is: `compose` sends the float32 shader
result straight to `to_u8`.

### 4.4 Cross-references

- **GLSL ES 3.00.** All 27 programs (3 basic/transition + 24 blend) compile and link as
  `#version 330 core` and as `#version 300 es` on this driver (the context accepts ES 3.00
  sources). This does not replace an ANGLE run (ARCHITECTURE 6.5).
- **KiriKiri Z** `visual/gl/blend_functor_c.h` (read through a summarising fetch, not
  copied). Its `ps_color_dodge5_blend_func` scales the source by the opacity first and returns
  without the final alpha mix that `ps_color_dodge` applies; `ps_diff5` does the same. That is
  the nexl-family behaviour that the ISA shows for modes 15 and 17 (output alpha 1;
  `s * alpha * a` in the divisor). KiriKiri works on 8-bit tables (`ps_color_dodge_table`).
  The HuneX shader is float and adds the d < 3/255 black rule. So the ISA formulas of
  compositing 2.3 stay authoritative.

## 6. Open points

1. **Oracle export model.** `tsuki.compose` has no model of the fp16 round-toward-zero colour
   export (compositing 2.1). Golden frame comparisons (ARCHITECTURE 10.5, T5 (b)) should
   apply it, or else allow 1 level per pass. Without it the aligned 13-layer frame reaches only
   99.56 % within 2 levels, below 99.9 %. This belongs to the compose / oracle owner;
   `verify_s3.py` has the model as `rtz16`.
2. **Blender precision of the PS4.** The PS4's CB rounding on RGBA8 targets is not known.
   The RX 9070 XT blends at about float precision with round-to-nearest. This needs PS4
   captures (`docs/status/ps4_captures.md`).
3. **Not covered here:**
   - per-tile textures (ARCHITECTURE 4);
   - mipmaps or minification quality for strongly zoomed-out large pictures (for example
     IMG0700_06_06 at zoom 0.15 in the opening);
   - the masked two-pass layer path (compositing 14.3);
   - an ANGLE / D3D11 run.

   None of these is a performance risk at the measured headroom: 30 full-screen blend layers
   take 1.33 ms at p99.
4. The static-layer cache was not built. The fallback was not triggered, and in this scene
   the zooming backdrop leaves nothing static to cache.
