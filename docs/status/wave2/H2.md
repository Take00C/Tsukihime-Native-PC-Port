How a consumer uses it:

```csharp

using GoldenSource gold = GoldenSource.Open();      // finds samples/golden/slice; movies need the game folder (TSUKI_GAME_DIR)
IGameData data = gold;
ScriptImage s = data.Script(3);                     // 37,752 bytes, 2,130 segment starts
AudioClip bgm = data.Audio(AudioBank.Bgm, 33);      // 8,258,048 stereo frames, loop 962000..8257999
```

What the slice does not hold throws `GoldenSliceMissingException` (a `KeyNotFoundException`): scripts other than 2 and 3,
text other than lines 0..7 in ja and en, fonts other than ja and en, any picture, audio entry or UI sheet that no traced
statement uses. An argument outside the game's own range (`Script(549)`, `Picture(6, 0)`) is an `ArgumentOutOfRangeException`.

## Conventions this fixes (GameFolderSource, package A3, must return the same)

These are the places where `IGameData`'s comments leave room. Each is checked against the Python oracle or the C# decoders.

- **`TextLine` is the engine's copy of the line** (`engine_line_hex`, VA 0x75F80): `off[id+1] - off[id]` bytes, empty when
  under 3, else at most 0x301 of them minus the CR LF. So no CR LF, markup intact, `$` not expanded. The raw blob bytes with
  CR LF are `RawTextLine` (golden only). Equal to a direct read of `script_text.mrg` for lines 0..7 in ja and en.
- **`FontPage` RGBA** is the oracle's `FontPage.rgba()`: palette in pixel-index order with the CSM1 swap, alpha 0x80 to 0xFF
  else `2a & 0xFF`. The slice stores only the coverage plane, so `GoldenSource` rebuilds the colour per coverage value (the
  channel-wise maximum over the palette entries with that converted alpha). That reproduces all 130 `rgba_sha1` of the
  manifest, and a test checks it again pixel by pixel against `palette[index]` read from the real `ft_*.mrg`. Page 0 is
  256 x 256, the other 64 pages 1024 x 1024 (the contract comment says 1024 x 1024 for all).
- **`Picture` tiles** are the stored tiles, border included, row-major, flag-0 tiles present with an empty `Rgba`;
  `Source` and `X`/`Y` are the oracle's `copy.src/size` and `copy.dst`; width and height are `out_width` and `out_height`.
  All 22 pictures equal what `ImageMzp.ToPicture` (A1) decodes from the game folder, tile by tile and byte by byte.
- **`Audio`** is the float PCM of the playable range, unclipped; the loop is `smpl` minus `fact[2]`, end inclusive, null
  when the entry has no loop or start equals end. The two loops that exist (bgm 33 and vse 598) equal the `smpl` chunks of the
  RIFF in the real banks.
- **`Script(k)`**: `SegmentStarts` are the statement offsets of the oracle; they equal `ScriptSegmenter.SegmentStarts` (C's
  tokenizer) on the same bytes, and the bytes equal the MZX0 + XOR 0xFF decode of the `allscr.mrg` section.
- **`Movie(i)`** is the movie table's `/app0/...` path under the game folder (explicit folder, `TSUKI_GAME_DIR`, or the folder
  the export was made from). All 134 paths exist; the four prologue files have the manifest sizes.
- **`BuildInfo.Source`** is the slice folder; size and SHA-256 are the manifest's `game.eboot`.

   already holds the data for `SceneIds`, the movie table, motions, glyph tables, config and text-box tables.

5. **A3 writes `GameFolderSource`** and then adds `class GameFolderSourceConsumerTests : SliceConsumerTests` (a few lines:
   the `Source` property). The abstract tests are source-agnostic by design; the golden-only extras stay in
