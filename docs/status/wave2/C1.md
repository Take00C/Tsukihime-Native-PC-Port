## Decisions and deviations

- **The port follows `tsuki.script` where it differs from the engine on malformed input** (the oracle is the reference; none of
  these occur in the retail data, which the hashes prove):
  1. The four name bytes must lie inside the segment (script.md 3.1 says the engine takes them even across a `;`).
  2. A segment of 0x300 bytes without `;` before the script end: the engine cuts it at 0x300, the reference raises
     `ScriptError`. C# cuts and sets `ScriptSegment.Truncated`; the caller decides (dev build: hard error).
  3. The readers are bounded by the statement: bytes past its end read as 0, where the engine would read the next statements.
     This only matters when a keyword tag's blind 5-byte skip runs past the `;`.
  4. `Arg.tag` accepts ASCII digits only (Python `isdigit()` also accepts other Unicode digits in `TEST_SCRIPT`'s UTF-8 text).
- `Statement.Args` starts at the separator byte (`name + 4`), as the contract says. Reader positions: inline `p0 = Args[1]`
  (`InlineReader.StartInArgs`), object `sep = Args[0]` (`ObjectParser.SeparatorInArgs`), textual arguments from `Args[1]`, or
  `Args[4]` for `Z` markers (`ArgumentList.StartIn`). Marker ids are read from the script, not the `Statement`, because the
  reference reads them past the segment end when the segment is short (`ScriptSegmenter.TryReadMarkerId`).
- The `Z` markers' inline readers still start at `_ + 6` (as in the reference), which reads the marker id as an argument;
  handlers of markers use `block` / `sub` and `ArgumentList` instead.
- Unlike `ExprUndefined` / `ScriptError`, nothing throws: `TryEvaluate` and `Split` return status values, so an argument such
  as `img1728` (a tokenizer stop, not an error) costs no exception on the hot path.
- The golden area is `samples/golden/script/` (own manifest). `ScriptFrontEndTests` and `ReaderFuzzTests` fail with the command
  that creates it when it is missing and the game folder is present; they skip only without the game folder.
