## What was done

**Spec first** (D owns this oracle):

- `docs/formats/compositing.md`:
  - new 2.6 "The MRT0 colour export: fp16 round toward zero": the model, why it matters, and what was measured;
  - new 6.1 "Executing a list": the reference executor and the GPU executor;
  - three new rows in section 11, the API in section 13, and open question 14 #9.
- `tools/tsuki/compose.py`:
  - `rtz16`, `export_mrt0`, `EXPORTS` (`"rtz16"` is the PS4; `"f32"` is the old behaviour);
  - `draw(..., export=)`, which defaults to `"f32"` so existing callers are unchanged;
  - `select_shader` and `shade`, which take P2 from the blend state actually used;
  - `execute_list`, an aligned display-list executor. Every pass is stored as UNORM8, quads with vertex alpha 0 are culled, and capture surfaces are supported;
  - `levels_error`;
  - the CLI `python -m tsuki.compose run <folder>` (lists.json in, ref.rgba out).
- The export model was checked against the ISA (`tests/Tsuki.Tests.Render/Compositor/check_export_model.py`). On the `test_compose.py` inputs (35 PS x 4 parameter vectors x 4,096 lanes = 2,293,760 finite channels), the formulas match the interpreter's export bit for bit on 10.22 % of channels as float32 and on **99.98 %** after `rtz16`. The worst remaining difference is 1 fp16 ulp (relative 4.88e-4).

## Open issues

1. **Contract (lead).** `DrawCmd` has no field for a texture's transition parameters (lo, hi, inv). The executor reads them from the texture cache (`TextureCache.SetTransitionParams`), which mirrors the PS4 texture object (+0xF0..+0xFC, set every frame by 0xD73B0). D2 must therefore call `SetTransitionParams(rule, FadsCommands.Frame(...))` every frame. The alternative is to add a `TransitionParams?` field to `DrawCmd` in `src/Tsuki.Engine/Contracts/`. The contract should also state that `Vertex.U/V` are normalised [0, 1] coordinates. The executor accepts strip order (TL, TR, BL, BR) and cyclic order.
2. **Lead / L-2 / H: the timing criterion depends on machine load.** With other agents saturating the CPU, single frames over 16.7 ms appeared even in frames that uploaded nothing.
   - The asserted configuration (pre-created texture pool and an AboveNormal frame thread) gave 0 of 443. Before the priority change it was 1 of 722, with the machine 100 % busy.
   - The test can still fail on a saturated machine. Run it with the machine otherwise idle (T7) to separate the scheduler from the environment.
   - Proposals: ARCHITECTURE 4.3 rule 4 should prefer the pool, which needs a prewarm policy (which tile sizes, how many, when; the M4 prefetcher knows the coming scene). H1's main loop (`Tsuki.App/MainLoop.cs`) should run the frame thread AboveNormal.
   - Neither change to H1's main loop was made here: it is not a D1 folder.
3. **Lead.** `Support.cs` has a copy of the `[GameDataFact]` rule, because Tsuki.Tests.Render does not reference Tsuki.Tests.Data. Link `tests/Tsuki.Tests.Data/GameData.cs` into `Tsuki.Tests.Render.csproj` (not my folder) and delete the copy.
4. **Lead / H.** `tools/tests/test_compose.py` should get tests for `rtz16`, `export_mrt0`, `shade` and `execute_list` (including `clip`, never-captured surfaces and `captures=`), and the ISA bit-exact check of `check_export_model.py` as an assertion. `tools/tests` is not a D1 folder. H3's `render.py` can use `compose.execute_list` with `export="rtz16"`; to carry capture surfaces from frame to frame it passes the same `captures` dict to every call.
5. **Not built (later D packages):**
   - the static-layer cache (optional, ARCHITECTURE 6.3);
   - masked two-pass and offscreen layers: target ids != 0 are created on demand but not tested against compose;
   - the YCbCr movie shader (PS #4) and `TextureKind.MovieFrame` planes; glyph pages and UI tiles go through the same cache but are not wired;
   - screen-effect presets (5.3); mipmaps for strongly zoomed-out pictures;
   - the 60 Hz present option; an ANGLE run and runs on NVIDIA / Intel drivers (only AMD was available). ES 3.00 programs were compiled and, in `ExportModelTests`, run in the AMD 3.3 core context. The colour export no longer depends on the driver (repair round), but the blender's rounding of ties still may (14 #9).
6. **[H] in the spec.** The vertex-alpha-0 cull is applied to fills too, in both compose and the GPU executor. The PS4 blender's RGBA8 rounding is unknown (compositing 14 #9).
7. **Not run:** `Tsuki.Tests.Synthetic` `ProjectRulesTests`. At 19:37 `src/Tsuki.Engine/Flow/LabelTable.cs` (package C) fails the build with CS0419. Tsuki.Render's P/Invokes (kernel32 `GetLogicalProcessorInformation`, `GetSystemTimes`) are allowed: the native-interop rule covers Data and Engine only.
8. **Suite timing.** `UploadTimingTests` waits up to 8 min for `artifacts/gpu.lock` when another agent holds it (one run waited about 3 min). Each timed test opens a visible window for about 7 s, and a 50 s watchdog ends the loop.
9. The S3 spike sources are lifted. They can be deleted with the other spikes after M2 (decision 6).
