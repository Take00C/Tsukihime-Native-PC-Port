## 2. What was built

`src/Tsuki.Media/` (2,996 lines with the tests and the oracle):

| file | content |
|---|---|
| `Audio/RiffAtrac9.cs` | RIFF/WAVE ATRAC9 header with the strict checks of `parse_wave` (audio.md 2.1-2.3); playable loop `[smpl - fact[2]]`, null when start == end |
| `Audio/Atrac9Decoder.cs` | libavcodec `atrac9` with 12-byte extradata and one 512/384-byte superframe per packet, no demuxer (S1); FLTP interleaved by copies; `Reset` for a future streaming BGM; loads FFmpeg through H1's `FfmpegLibrary` |
| `Audio/HeVag.cs` | port of `audio_hevag.py`: header, 128 x 4 table (K / 8192), float32 left-to-right prediction, truncation, unclamped history, end-marker trim, the flag loop |
| `Audio/MediaAudioDecoder.cs` | the `IAudioDecoder` (contract unchanged): vag -> HE-VAG / 32768, every other bank -> ATRAC9 playable range |
| `Mixer/AudioMixer.cs`, `Mixer/Voice.cs`, `Mixer/MixerCommand.cs` | float32 stereo 48 kHz mixer: 64 voice slots added in id order, periods of at most 1024 frames, commands posted from any thread and applied at a stamped output frame (or the next one), engine pan law, linear gain and pan ramps (default 800 frames = one 60 Hz step), loops with a repeat count (never past the loop end), stream voices (`IMixerSource`), nothing clipped. `Render(Span<float>)` is Tsuki.Platform's `AudioRenderCallback` |
| `Movie/FrameSelector.cs` | the 60 Hz frame choice with the 4 ms cadence lock (S2 `Player.Tick`), pure; counts holds, early switches and drops |
| `Movie/AudioClock.cs` | media frames taken + time since the callback - one device buffer, clamped to one chunk until drained, never backwards (S2 `AudioOut.Clock`); timestamp frequency injectable for tests |
| `Movie/MovieAudio.cs` | `PcmRing` (SPSC, 4 s) and `MovieAudioSource`, the mixer stream voice that feeds the clock on every read |

`tools/oracle/audio.py`: area `audio`, parts `hevag` (`vag.tsv`), `atrac9` (`streams.tsv`, nightly,
left out of `--quick`) and `mixer` (`render_mix`, the reference mixer; `synthetic.json/.f32` with its 3
clips, `real.json/.f32` on bgm #33 across its loop seam, vse #598, voice #15616, a duck and a 60-step
SoundModel-style fade). The module docstring is the mixer contract (ramp formula, pan law, loop and
command rules); both sides do the same float32 operations in the same order.

Tests: `tests/Tsuki.Tests.Synthetic/Media/` (35: HE-VAG 6, mixer 16, cadence and clock 12, movie audio 1)
and `tests/Tsuki.Tests.Data/Media/` (14: HE-VAG, all ATRAC9 streams, the slice clips, 9 mixer chunkings,
2 SDL pull runs). The data tests read golden files only after checking size and SHA-1 against the area
manifest, and leave nothing in `%TEMP%`.

## 5. Open items

1. **Movie thread not ported.** S2's `Ffmpeg.cs` (demuxer, software H.264 with frame threads, AAC +
   swresample), `MoviePipeline.cs` (demux and decode threads, 8 pinned frame buffers, seek trim) and
   `Queues.cs` (`FrameQueue`, `PacketQueue`) still need a Tsuki.Media port, software decode only (no
   d3d12va with 1 thread), feeding `PcmRing` and `FrameSelector`, with a headless test on
   `prologue_en.mp4` (11,660 frames; 18,655,997 AAC samples per channel = `duration_ts`). About 1 h.
2. **AudioCommand -> mixer translation** (stream numbers, `open_*` / `close`, `set_volume0`, `set_loop`
   counts, `set_start_sample`, `PlaySystem` as an L / R pair at pan -1 / +1, clips from `IGameData.Audio`)
   is not written; it fits E2 or the M2a integration. The mixer already takes every needed operation.
3. `src/Tsuki.Engine/Movie/` is untouched (the engine only needs `MovieClock`, which is a contract).
4. **Mixer semantics are ours.** ARCHITECTURE 7.1 says "linear ramps" without a length; E1 chose an
   800-frame (one 60 Hz step) default ramp so the SoundModel's per-step volume staircase becomes a
   continuous fade, with the exact formula in `tools/oracle/audio.py`. L2 should record this in 7.1.
5. **Device playback** (`AudioOutput.OpenDevice(mixer.Render)`) was not run in E1: the wiring is the
   same callback the pull test uses, and S1 measured the device path. The full mixer under load (2 BGM,
   20 SE, voice) is still a T7 measurement.
6. **Shared change for the lead:** `tests/Tsuki.Tests.Data` reaches `Tsuki.Platform` (for the SDL pull
   test) only transitively through `Tsuki.Cli`. An explicit `ProjectReference` would make that robust.
7. **Shared build at the end of the session:** `src/Tsuki.Data/Catalog/GameCatalog.cs` (another package's
   in-progress edit) failed with CS0120, so the last E1 builds used `-p:BuildProjectReferences=false`
   against E1's own earlier Tsuki.Data build. `Tsuki.Tests.Synthetic`'s
   `LvAndBuildCheckTests.TsukiDataNeverReadsAFileWhole` (a Tsuki.Data source scan) failed then too; it
   is not E1 code.
8. The ATRAC9 nightly test runs in every `Tsuki.Tests.Data` run (14 s); tag it if that is too long.
