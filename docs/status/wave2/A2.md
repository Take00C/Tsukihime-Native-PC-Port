## Open issues

1. **Register the area in `tools/oracle/run.py`** (not an A2 file): `AREAS` needs `"catalog": "oracle.catalog"`. Until then `python -m oracle.catalog [--verify|--parts ...]` registers itself with the runner's table.
2. **Wire the probes into `BuildCheck`** (`src/Tsuki.Data/Verification/BuildCheck.cs`, not an A2 file): in `Runner.CheckEboot`, after the SELF magic and Hunex probes, add
   `Results.AddRange(EbootProbes.Run(data));` (the ids are disjoint from the existing ones, `SliceCrossCheckTests.TheBuildCheckAndTheStructuralProbesAcceptTheSameFolder`). Then `BuildCheckTests` should also
   get the damaged-table cases; `Tsuki.Cli verify` prints the new lines without a change. The font-table probe of RR 3.3 item 2 is still missing (A3).
3. **`IEbootTables` is still empty** (`src/Tsuki.Engine/Contracts/IGameData.cs`, lead-owned). `GameCatalog` holds what the contract needs for RR 3.2's first rows: `Images` (`CatalogEntry`), `PictureNames`, `Movies`, `PrologueIds`,
   `LanguageSuffixes`, `UiTables`, `UiText`, plus `Resolver` and `NameIndex` for lookups. A3's `GameFolderSource` should call `GameCatalog.Load`; `IGameData.Movie(index)` is
   `Movies[MovieRules.IndexForLanguage(id, lang)].FileName` under `image/movie`.
4. **Not ported, on purpose:** `ARCHIVES` and `PARTS_MRG` (prose tables for documentation), `iter_catalog` / `EntryInfo` / `export` (the census and the CSV / ffprobe tooling; the census is A3's T0),
   `CatalogResolver.render` / `thumbnail` / `crop_rect` (pixel composition; the runtime composes on the GPU, and `compose` is not ported either, see A1 issue 4), `load_picture_names` (the content search
   for the name list; the fixed-address reader is equal, checked by the exporter), `selfelf.iter_strings` and the `__main__` dumps, `uitext.iter_block`. All are tooling.
5. **The Python reference has one crash that C# does not copy:** `classify_name("TITLE_PARTS_TH")` (a `_TH` suffix on a set without a thumbnail variant) raises `KeyError`; the C# port returns `Unknown`. No retail name
   triggers it; the oracle's name list leaves it out. The same applies to a set found only through `f"{set}_{lang}"`.
6. **Names are bytes or ASCII.** The NAM key and the script key take `ReadOnlySpan<byte>` (the Shift-JIS rule needs bytes); the `string` overloads accept ASCII only and throw `ArgumentException` otherwise, because
   ARCHITECTURE 1.5 forbids code-page APIs. The Python resolver round-trips non-ASCII ids through cp932; for valid input this is the identity on bytes, which the C# path uses (tested on `\x82\xa0`).
7. **`GameCatalog` keeps eboot.bin (12.7 MB) in memory** for as long as it lives, because `UiText` is read on first use and the readers work on spans of that array. If memory matters,
   call `UiText` once and drop the catalog's `Eboot`, or ask for a copy-out variant.
8. `ImageCatalog.Read` is strict where the Python `Eboot.image_table` is (pointers in the text segment, names `[A-Za-z0-9_]+\.(mzp|MZP|mrg|MRG)`, name pointer 0, contiguous records, count 14,744) and in addition
   requires the empty slots to have name1 = 0 and cache = -1. Another build would be refused, as RR 3.3 wants; `expectedRecords: null` relaxes only the count.
9. `SelfImage.FindPlt` mutates `ImportedSymbol.PltVa` (as the Python does); call it once per list.
10. Timings are with a warm file cache. The first call after process start pays JIT (the Debug test run measured well under 1.5 s).
11. **Naming caution for A3 and the lead:** the new namespace `Tsuki.Data.Eboot` has the same simple name as the property `IGameData.Eboot`. Inside a class that has a member called `Eboot` the member wins, so
    nothing breaks today (the whole solution builds), but code in `namespace Tsuki.Data.*` that wants the namespace must write `Eboot.` only where no member of that name is in scope, or add a `using Tsuki.Data.Eboot;`.
