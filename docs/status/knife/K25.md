# K25: other players' dumps (folder layouts, build identity, tables located by content)

Package K25 (label `k25`), run on 2026-10-30 on top of commit f74a533 while two other agents worked beside it (screenshot / toast / input; a read-only audit). Nothing is
committed. Builds in `artifacts/k25` (Release, `-warnaserror`, 0 warnings), every game run hidden and muted (`--hidden --mute`, `SDL_AUDIO_DRIVER=dummy`) on its own
`--save-dir` under `scratch/k25/`, the launcher only in its offscreen modes (`--render`, `--selftest`) on temp `--data` profiles. The game folder and the update folder
beside it were only read; the other-layout tests reach them through directory junctions under `scratch/k25/layouts/` (deleted as links afterwards). `artifacts/play*`,
`artifacts/dist`, the user's `%APPDATA%\Tsuki`, desktop and Start menu were not touched. No knife code was translated; `docs/THIRD_PARTY.md` is unchanged.

Goal: the port works with other players' dumps, not only this machine's. Before K25 it accepted exactly one folder shape and one eboot (by SHA-256), and every table
reader held a fixed virtual address of that eboot.

## 1. What this machine turned out to have

The user's folder `...\CUSA47999` holds the eboot the whole port was verified on (SHA-256 `c2843415...`, 12,767,802 bytes). Beside it sits `CUSA47999-patch`, left by
the PKG extractor: an `eboot.bin` of the same size with SHA-256 `9e74a735...`, `param.sfo` with `APP_VER 01.01`, `CATEGORY gp` and `TITLE_ID CUSA47999`, and three data
files (`allpac3.hed/.mrg`, `allscr.mrg`, `script_text.mrg`) that differ slightly from the merged folder's. The two eboots differ in **418 bytes in 76 runs**
(`scratch/k25`-free Python check, re-done by `EbootLocatorTests.TheSecondEbootOfThisMachineHasEveryTableAtTheSamePlaceWithTheSameBytes`): the SELF header's digest, six
code patches in the text segment (0x3BE80, 0x3BF45.., 0x70C74.., 0xF5550: a `call` replaced by `mov eax, 1000000000`; 0x2EC328 / 0x2F151C in `.eh_frame`), the SDK
version word of the process parameters (`11.00.80` -> `05.05.00`) and 62 module version words in the dynamic data. The patch folder's eboot is the **1.01 eboot of the
5.05 / 6.72 / 7.xx backport package**; the merged folder's is the official 1.01 update's. Not one byte of any table differs between them, so the backport eboot went into
the known-builds table as a second known build (status "tables byte-identical"), not as verified.

That gave a real second eboot and a real split layout to test on, which the brief did not count on.

segment (2,419 of them): the addresses the code loads tables from, used as candidates and as a cross-check.

(a cell table of non-rectangles, a float table of non-floats) and the table is then reported missing rather than misread. The locator takes 0.2 s on the verified
eboot, 0.4 s on the backport eboot (a cold start).

## 4. Decisions

1. **The update wins** (the console's rule): in a split dump the update's files, `eboot.bin` and `param.sfo` take precedence over the base's. **Exception:** when the
   base folder's own eboot is a known build whose version is at least the update's `APP_VER`, the base is used alone and the update folder is noted as "not needed".
   Without it this machine's verified configuration (the official 1.01 eboot and data in `CUSA47999`) would have been replaced on every start by the backport eboot and
   the repack's three data files that happen to sit beside it. The launcher's Build row says which rule applied.
2. **Nothing is guessed**: an eboot that is not a known build is located table by table; one missing table refuses the start, in the player's language, naming the build,
   the eboot's hash and the tables, and the log holds the per-table report for the bug report.
3. **`Accepted` stays strict** (the verified build, complete); **`Usable`** is the new word for "another eboot, every table located, data complete". The launcher's
   `Ready` state means usable; the folder row and the chip say "not the verified build" when it is not.
4. **Counts of another title id** are notes, not failures (another data release has other counts); for CUSA47999 the FORMATS 2 counts stay failures.
5. **Languages**: selectable = text and glyph pages and UI sheets present. Korean has sheets but placeholder text and blank glyphs in this release, so it stays out, as
   before; movies fall back to Japanese and do not decide.

## 6. What cannot be tested here (honest limits)

- **Another data release or another title id** (a Japan-only or a Western release, a 01.00 base game's eboot): no such dump is on this machine. The locator was calibrated on
  two eboots of one release that differ by 418 bytes outside every table, so every "anchored" offset and both "engine order" namings are untested across a real
  relayout. On such a build the validators decide: a table that passes a wrong guess by accident would be misread. The byte-flip and zeroing tests show that a damaged
  table is refused, not that a shifted one is found.
- **A real 01.00 base folder + 01.01 update**: simulated with a base whose eboot is the verified one with a code byte flipped (an unknown hash) and the real update folder;
  the base's data files are the merged folder's through junctions, so "the update's data files differ from the base's" was exercised only for the three files the update
  carries.
- **shadPS4's `CUSA47999-UPDATE` naming** and the `-app` naming: synthetic folders only (`GameLayoutTests`).
- The Korean slot: hidden because the data says so; what a dump with real Korean text would need in the UI (fonts.md: the ko glyph pages are blank here) is not known.
- The scene-node count rule (ids below 3000) and the record-table naming are hypotheses that hold on this release; a dump that breaks them makes the locator report a
  wrong count or wrong names only if the validators do not catch it (the scene nodes are range-checked, the glyph tables count-checked against their lookups).

## 7. PS4 versus Switch

Nothing new: knife bundles its tables, the PS4 reads them from the eboot; K25 only removes the fixed addresses from the readers.

## 8. Open issues

1. The anchored tables (section 3) deserve content signatures of their own if a dump ever shows a shifted layout; the report names them, so a player's log will say.
2. `BuildMatch.Verified` covers every known eboot (the verified one and the backport); the launcher's `IsVerifiedBuild` tells them apart. A third word in the enum would be clearer.
3. The launcher's texts are English (as before, K20 open issue 2); the game's are localized.
4. `scratch/k25/layouts/manual` holds junctions into the game folders for the launcher renders; they are plain reparse points and were removed at the end of the package (`rmdir` on the links). The test fixture removes its own.
