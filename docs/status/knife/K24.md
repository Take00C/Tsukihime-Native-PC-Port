Package K24 (label `k24`), run on 2026-10-30 on top of commit f74a533 (K20..K23 committed). Nothing is committed. Builds in `artifacts/k24` (Release, `-warnaserror`,
0 warnings), temporary profiles under `scratch/k24/` and the test runner's temp folder, every game run hidden and muted (`--hidden --mute`, `SDL_AUDIO_DRIVER=dummy`) on its own
`--save-dir` with `--screenshot-dir` under `scratch/k24/` (never the user's Pictures folder), the launcher only in its offscreen `--render` mode on a temp `--data` profile.
No window was shown. `artifacts/play*`, `artifacts/dist`, the user's `%APPDATA%\Tsuki`, the real desktop, Start menu and clipboard, and the game folder (read-only) were not

input-mapping and config-row code and their tests were edited (`Tsuki.Data` and the launcher's folder checks belong to the package running beside this one).

## 1. The complaint, and what was wrong

The user takes Windows screenshots (Print Screen, Win+Print Screen, Win+Shift+S, Alt+Print Screen). K21 had bound **Print Screen** to the game's own screenshot too, so a
Windows screenshot also made the game save a PNG and show a 52 px toast across the top right, `スクリーンショットを保存しました: Tsukihime_2026-10-30_21-15-02.png`, for 3 s;
the Windows picture then carried the game's toast (the game's own PNG never did, K21's capture-before-toast rule). Three changes:

1. **F12 alone takes the game's screenshot.** `EventPump.IsScreenshotHotkey` is `key == SDLK_F12` (no repeat); Print Screen is an ordinary key to the pump now, and no other
   key reaches `ScreenshotRequested`. `PcInput.Classify` (the keyboard-state reading, now a pure function over the scancode bytes so it can be tested) keeps Print Screen and
   F12 out of "some key" (`PcKey.Other`: a Windows screenshot on PRESS ANY KEY does not press it) and adds one rule: **while the Windows key (LGUI / RGUI) is held, no key counts
   at all**, so Win+Shift+S never moves a menu cursor with its S, Win+Print Screen / Win+G / Win+D never press anything. Alt+Print Screen: Print Screen is ignored, the Alt is
   a key like any other (it was before; the pump's Alt+Enter is unchanged). `InputMapper.Bindings` and the launcher's `KeyTable` row read "F12" (the Controls page shows it,
   `GameLauncherTests` ties the two lists), `AppArgs` usage and the README say F12 only.
2. **The toast is small, brief and in the bottom left corner.** `UiToast`: a 40 px high rounded box of the pill palette at x 40, bottom edge at y 1008 (above the menus'
   guide bar, which starts at y 1023, and left of the config page's edge at x 407 in English), the words at the key caps' scale 0.32 (the pills' labels are 0.36, the headings
   0.4), **fade-in 6 frames, hold 72, fade-out 12 = 90 frames = 1.5 s** (K21: 8 + 150 + 24 = 3 s at the top right, 52 px high, scale 0.4). `ShowToast(text, brief: true)`; the two
   WebSocket toasts of K23 (an address, an error to read) pass `brief: false` for the longer hold (`LongHoldFrames` 150). The `ScreenshotSaved` / `ScreenshotFailed` strings lost
   their `{0}`: ja スクリーンショットを保存しました / スクリーンショットを保存できませんでした, en Screenshot saved / The screenshot could not be saved, zc 已保存截图 / 无法保存截图,
   zt 已儲存螢幕截圖 / 無法儲存螢幕截圖; the file path and the system's words stay in the log (`screenshot saved: <path> (W x H)`, `screenshot failed: <path>: <error>`). The
   capture-before-toast rule (`HideToast` until the frame is read back) is unchanged, so the game's own PNG still never shows it.
3. **Config > System > Screenshot Notice** (On by default; Off saves the picture and shows nothing): `PortRow.ScreenshotNotice` / `CtlKind.ScreenshotNotice`, two Off / On pills
   under the Window Size row (it is about the picture of the window, so it sits with the window rows, above the three text-output rows); the band is seven rows now (`BandFor(7)`
   = 440, the tab scrolls 750 + 440). Heading: ja スクリーンショット^通知 (two lines at 0.36, as the long English headings: the one-line word ran up to the Off pill in the first
   render, `scratch/k24/ui/` before the fix), en Screenshot Notice, zc 截图提示, zt 螢幕截圖通知. `IUiPortSettings.ScreenshotNotice`, `PreviewPortSettings` (on), `PortSettings`
   (settings.ini **`screenshot_notice=on|off`**, absent = on, saved at once with its comment line, `AppSettingsData.ScreenshotNotice`), `GameApp` shows the toast only while
   it is on and logs `(notice off)` after the saved / failed line otherwise.

1. Not tried by hand (nobody at the keyboard, no window shown): F12 and the Windows screenshot keys from a real keyboard. The pump path is tested with the real SDL F12 event pushed,
   the key classification on the scancode bytes SDL hands out; what Windows delivers to the window for Win+Shift+S (the Win and Shift key-downs, and whether the S arrives at all)
   was reasoned from the hotkey rules, not watched. If the user still sees the game react to a Windows screenshot key, the log line `screenshot requested (<key name>)` says which
   key SDL reported.
2. The Japanese toast is 381 px wide and ends 14 px past the config page's left edge while a menu is open (section 3); a shorter Japanese sentence (保存しました alone) would keep
   it clear but says less. Left as it is.
3. The toast's place is fixed at the bottom left; a message window line that reaches the corner is covered for 1.5 s. The PS4 message window's text starts further right.
4. Every port toast is brief now (1.5 s), the two WebSocket toasts excepted (2.8 s). The clipboard toast ("Text copied to the clipboard", once per run) is brief too.
5. The Screenshot Notice switch governs the screenshot toasts only; the other toasts have no switch.
