# K4: history ring, saves and system data

Owner: package K4. Spec: [`docs/formats/adv_state.md`](../../formats/adv_state.md) (the verified PS4 behaviour wins over knife). Code:
`src/Tsuki.Engine/Save/`. Oracle: `tools/oracle/save.py` (area `save`, local `samples/golden/save/`, never committed).

Status: **done**. The history ring, rewind, previous / next scene, the scene stack, the backlog, save slots, quick / auto save, the
system data, the save file and the PS4 image import are built, and every part that has game code behind it equals that code.
Not done: the glue to the interpreter, stage and sound objects (the interpreter's job, see "Integration"), the scan-mode load of
older saves, and the asset prefetcher the PS4 restarts after a rewind (see "Open issues").

## The API (for the interpreter, package K3)

Everything is in namespace `Tsuki.Engine.Save`. One `AdvHistory` per game, one `AdvLiveState` that the interpreter fills, one `SaveStore`.

```csharp
var live    = new AdvLiveState(vars, store.SystemData.Config, scene, committed);  // or new AdvLiveState() in tests
var history = new AdvHistory();
var store   = SaveFile.ReadWithFallback(path, out bool usedBackup) ?? new SaveStore();
```

**Pushing (one call per `IHistorySink.Push`).** Fill `live` from the engine, then
`bool pushed = history.Push(live, cmdOffset, resumeOffset, kind)`. `cmdOffset` is the offset of the `;` before the statement's `_`
(Script_Step passes `name - 2`), `resumeOffset` the end of the statement, `kind` as adv_state.md 2.3 (`AdvHistory.Kinds`). The gates (scan
mode, F929, byte 0x16541F4, F1102) are inside; the call returns false when nothing was pushed. After the push, in the engine's own order:
`SetNewestMessageText(bytes)` (the `_ZM` / `_MSAD` / `_ATSV` text copy), `SetNewestVoice(id, character, speaker)` (voice play, not for a
re-displayed line: `live.RestoredFromHistory`), `UpdateStaging(history.Newest, live)` at the sites that call Staging_SetSnapshot (`_ZM`,
`_MSAD`, `_ATSV`, `_SELD`; it applies the caller rule: no blocking effect, kind not 11 / 12, F823 <= 1), `PushSceneStack(effectBlockingBits)`
for `_ATSV`. `OnMessageShown()` counts the scene-start counter down at each `_ZM`.

**Restoring.** `RestoreOutcome o = history.Restore(index, fromHistory, live, scripts)`. The variable copies are already in `live`
(`live.ScriptOffset` is where the interpreter resumes: the record's `CmdOffset`, so the saved command runs again; for a rewind to a
message it is `ResumeOffset` and the line is re-displayed). The outcome lists what the engine must still do: `ReloadScript` (load
`live.ScriptNumber`), `StopEffectSlots`, `Bgm` / `BgmTrack` / `BgmVolume` (kind 2), `LoopSe[]` (kinds 3..5: per channel restart or stop, with the
four arguments the PS4 passes), `RebuildFromCommitted` (kinds 1 / 9), `ShowRecordText` (kind 7), `FlushPending`, `F967Reset`, `Redisplay`
(text, end code 0/1/2, name-plate bytes), `ScenePopped`, `Config04Hook`, `StagingUpdated`. `scripts` (`ScriptBytesProvider`: script number ->
decoded bytes) is needed only for a rewind to a message.

**Operations.**

| call | engine meaning |
|---|---|
| `RewindStep(live, scripts)` -> `RewindResult` | one step of the held rewind action (after Adv_Rewind's own wait checks, which stay with the interpreter): undoes the cursor record unless it is a message / choice, walks back to the previous page start, undoes the records in between, restores and re-displays the target. `Stepped`, `Target`, `Restores` (in order), `Resync` (then the stage rebuilds from `live.Scene` / `live.Committed` and sound restarts from the live variables, VA 0x7E4E0 / 0x7E620), `FlushPending`. `CanRewind`. |
| `PreviousScene(live, effectBlockingBits, waitFlag10, out flush)` | the previous-scene action after its dialog (null = nothing to restore). `CanGoToPreviousScene(...)` lights the button. |
| `RequestSceneJump(dir, waitFlag10)`, `TakeSceneJumpRequest()`, `NextSceneRunning`, `EndNextScene()` | the scene-jump request word (0x16541F8) and the next-scene skip flag (0x120A6D2). The skip itself is the interpreter's loop; it ends at the commands of adv_state.md 5.2. |
| `BacklogEntries()` -> ring indices, newest first | Backlog_Open: the messages of the earlier pages (empty = nothing to show). Each entry's text is `history.Record(i).MessageText`, its voice `VoiceId`, its page-end flag `AdvHistory.RecordF8(rec, 799)`. |
| `BacklogJump(ringIndex, live)` | restore the entry (the command runs again) and drop the scene starts after it; null = invalid entry (error sound). The caller stops BGM / voice first and clears the wait state. |
| `LoadSlot(slot, live)` / `store.Load(n, history, live)` | Slot_Load. Throws `InvalidDataException` for a slot without its end marker. The caller clears the skip latch (`0x17DB230 &= ~2`) and re-creates the stage. |
| `store.SaveManual(n, history.Staging, date, thumb)`, `QuickSave`, `AutoSave` | Slot_Store / QuickSave_Store / the FIFO; false while the staging is empty. Manual and auto saves set the F1118 bit, the quick save does not. `UpdateLatestSlot` is called by the saves. |
| `SaveFile.Commit(path, store, vars)` | copy G[0..499] into the system data, then the atomic write (`SaveFile.WriteAtomic`; temp file in the same folder, flushed, `File.Replace`, previous generation kept as `.bak`). |
| `SaveFile.ReadWithFallback(path, out usedBackup)` | null when there is no file; `SaveFormatException` when file and backup are both damaged. `FromBytes` / `Read(Stream)` / `ToBytes` / `Write(Stream)` for other sinks. |
| `SaveFile.ImportPs4Image(bytes)` / `ExportPs4Image(store)` | the 4 MiB console image (`savedata000`) <-> a store. |

**Where each `AdvLiveState` member comes from.** `Vars`: the interpreter's F/Z/G (the same object). `Scene`, `Committed`: the stage's scene
state (K2) as `SceneState` views. `BgmTrack`, `BgmVolume`, `LoopSeIds`, `SeVolA/B`, `SeArrC/D/E`, `Channels`: the sound model's channel
state (RAM 0x1654240..0x16543F0 region, K1c). `MessageText`, `Window164FD00/40`, `Speaker`, `TextBlock/Line`: the message window and Z handler.
`EffectActiveBits`, `EffectBlockingBits`: the stage's 14 effect slots. `LastMessageOfPage`: the WNTY state. `PageEndInstantLatch`: config +0x9C / +0x9D
latch (VA 0x56140). `WaitFlags*`, `Var16541*`, `RedisplayText`: the wait model; the interpreter may ignore them (they are kept so the
oracle covers the whole restore). `AdvHistory.Ps4StaleSeBytes` stays false in the game (the PS4 bug of record +0x36BC is not reproduced).

**IHistorySink.** K3's `IHistorySink` (GameHost.Save.cs) maps one to one: `Push(kind, position, resume)` -> set `live.ScriptNumber = position.Script`,
`history.Push(live, (ulong)position.Offset, (ulong)resume.Offset, (ushort)kind)`; `SceneStackPush()` -> `PushSceneStack(live.EffectBlockingBits)`;
`SetMessageText` -> `SetNewestMessageText` (+ `UpdateStaging` for `_ATSV(1)`/`_ATSV(8)`); `AutoSave()` -> `store.AutoSave(history.Staging, now)` then
`SaveFile.Commit`. The sink needs the `AdvLiveState` and `AdvHistory` in its constructor; I did not add the adapter because it would
reference K3's in-progress types.

## PS4 versus Switch (knife)

- knife keeps a history of Rust snapshots plus a separate scene ring; the PS4 stores one record layout in three places (ring, scene stack,
  both states of a slot) and the history code is the same for all of them. knife's "locked" entries (story movie, staff roll) have no
  counterpart: the PS4 stop rule is `effect_blocking_bits == 0`.
- knife's `can_prev_scene` / `prev_scene` count scene points; the PS4 rule (0xA23F0) also depends on blocking effects and on wait-flag bit
  0x10, which changes the allowed top (>= 2 instead of >= 1). The PS4 rule is implemented and verified.
- knife stores the stage as its own block in the Switch record; the PS4 record keeps two `SceneState` copies (script-side and
  committed). Layer rebuild after a restore therefore uses the committed copy for kinds 1 / 9 only.

## Findings that correct adv_state.md (all proved by the oracle or the disassembly)

1. 3.1 / 2.1: History_Restore writes `0x1654200`, `0x16541FC` and `0x1654204` from the record's voice id for **every** kind (0x7C9BB..0x7C9C7), not only for kinds != 0; the kind-0 re-display then sets `0x16541FC` and `0x1654200` to -1.
2. 3.2: the name-plate flags `0x16541EC` / `0x16541F0` of the re-display take the value of the **original** byte `0x164FD40` (the `setne` follows the compare before the byte is zeroed), so they equal the common part's value.
3. 3.2: the statement-text buffer `0x16537E0` is not cleared: the text and one NUL are written over its old contents, and `0x1653AF0` is a copy of all 0x300 bytes. The end code is 2 (not 0) also when the text ends at `)` or after 0x300 bytes **and** the instant-page latch (VA 0x56140) is set **and** F799 != 1.
4. 5.1: the loop that undoes the records between cursor and target compares signed indices (0xA22E0..0xA22F5). When the ring has wrapped and the target index is above the cursor, no intermediate record is undone, only the cursor record (when it is not a message) and the target. Reproduced and verified (60 cases).
5. 5.3: "previous scene" decrements the real stack top before calling 0x7E790; 0x7E790 then sets top = n - 1.
6. 5.4: Backlog_Open does not test the serial of the records it lists; with a freshly cleared ring (n = 1) the single entry is dropped by the count == 1 rule. The list is also dropped when no record from index 1 on has F799 == 1.
7. 7.3: Slot_Load resets the sound arrays to loop id -1, pitch word 100, other arrays and the channel table cleared (channel entry +4 word, +8 and +0xD qwords -1) and BGM -1 before restoring; those values are `AdvLiveState.ResetSound` (also a new game's state).
8. 7.2: the latest-slot rule of commit mode 2 scans slots 0..138 and a strictly newer date wins (lowest index on a tie); a console image written by the quick save path can carry a stale latest-slot word, which `ImportPs4Image` recomputes instead of rejecting.

## Open issues

1. **Glue**: nothing yet fills `AdvLiveState` from the stage, sound model and message window, nor consumes `RestoreOutcome` (K3 / K2 / K1c; the table above says where each member comes from). The rewind prefetch the PS4 starts after a step (0xA0740, 0x7ECB0, Script_Prefetch) is an optimisation and not modelled.
2. **Re-display layout** (adv_state.md 3.2: name plate and message box laid out with Text_Layout, text colours by config +0x2A, offset 768.0 for 0x174DAF0): the textbox code owns it; `Redisplay` gives it the text, end code and name-plate bytes.
3. **Voice replay volume** after a scene restore (VA 0x7EB19): `SceneRestoreResult.ReplayVoiceId` / `ReplayVoiceCharacter` are given; the config row of a character (VA 0x3D2D0) is not mapped. The `_ZM` that runs again plays the voice through the normal command, so this only matters for a restore that lands on a voice line without re-running it.
4. **Scan-mode load** (VA 0xA3050, slots without the end marker): not supported; `LoadSlot` and the file reader reject such slots. Every slot the v01.01 code writes has the marker.
5. No retail PS4 save exists here: the import was tested on images made by the game's own save code (the three engine-made slots) and on synthetic images. Config +0x5A..+0x75 (two persisted 14-byte records) are carried as bytes; their meaning is open (adv_state.md 7.5).
6. Slot thumbnails are stored as given; capturing them, choosing the format and drawing the save list are the UI's job. The save list title is `SlotImage.SceneVariable` (F22) -> text id F22 + 0x18C.
7. Time: `SlotDate` is the caller's local time; `SaveStore` never reads a clock. The 300-frame quick-save cooldown (VA 0xDF29FC) is the caller's.
8. `SaveFormatException` derives from `IOException` (`InvalidDataException` is sealed); `AdvHistory.LoadSlot` throws `InvalidDataException` for a bad slot.
