# K34: the text-break marks (click-wait icon) of the console, decoded and drawn

Package K34 (label `k34`), run on 2026-10-31 on top of commit cbf260c. Nothing is committed. Builds in `artifacts/k34` (`-warnaserror`, 0 warnings).
Every game run hidden and muted (`--hidden --mute --fast`, `SDL_AUDIO_DRIVER=dummy`) on its own `--save-dir` under `scratch/k34/`; `artifacts/play*`,
`artifacts/dist`, the user's `%APPDATA%\Tsuki`, `%APPDATA%\shadPS4`, `D:/TsukihimePort-public`, `D:/TsukihimePort-release` and the game folder (read-only)
were not touched. No knife code was translated (everything here is from the PS4 eboot; `docs/THIRD_PARTY.md` is unchanged). No PowerShell with Add-Type,
DllImport, P/Invoke, LoadLibrary, base64 or Invoke-Expression; the pictures were cropped with Pillow from `.venv`.

## 1. The issue and the answer

GitHub issue #1 (a player): the port lacks the text-break glyphs of the console. True: K3 item 8, K6 issue 4 and K8 issue 3 list the click icon as not
drawn, and followups.md said its source was undocumented. The PS4 draws three marks at the end of a message that waits for a click, all from DISP_PARTS:
a **crescent moon** that waxes and wanes at a wait inside a page (child 4), **four stacked lines** at the end of a page (child 9, half alpha), and a **round
badge** in speech bubbles (child 53). The port now draws them from the real wait state in ja / en / zc / zt. The joined dashes (runs of `―` / `─` / `■` as
one stroke) were already right (fonts.md 5.6 is implemented in `LanguageGlyphs.DashVariantAt` / `DashGlyph`); a test and a screenshot now prove it.
There is no auto / skip indicator on the PS4 HUD (section 4).

## 2. What the eboot does (all read back under emulation; docs/formats/textbox.md 7.1 is the reference)

Tools: `scratch/k34/f_53630.asm`, `f_ca690.asm`, `f_eb890.asm`, `f_df760.asm`, `f_564a0.asm` (disassemblies), `scratch/textbox/hud_53cf0.asm` (the HUD),
`scratch/k34/tables.txt` (constants and the three frame tables), `scratch/k34/icon_emu.py` (the HUD run frame by frame under unicorn; the same code is
`tests/Tsuki.Tests.Data/Oracle/gen_click_icon_golden.py` -> `samples/golden_data/click_icon_oracle.json`), `scratch/k34/bubble_probe.py`, `block_hdr.py`.

1. **Pictures and slots** (registration table VA 0x780C90, records 0x780FC0 / 0x780FD8 / 0x780FF0; `samples/ui_misc/ui_texture_slots.csv` rows 109..111):
   UI slot 2 = DISP_PARTS child 4 (4095 x 39: 105 cells of 39 x 39, the moon), slot 3 = child 9 (4095 x 39: 105 cells, the last blank, the lines), slot 4 =
   child 53 (2537 x 46: 59 cells of 43 x 46, the badge). All four languages carry the same three sheets (decoded in `scratch/k34/disp/`; the cells at 4x in
   `cells_en_04_black.png` (moon phases), `cells_en_09.png` (line stacks), `cells_en_53.png` (badge)). Depth byte 0x14: size modes 0, so a cell draws at
   exactly 0.333 units per texel (float32 0x3EAA7EFA at VA 0x1A7094 and 0x1A7170).
2. **Frame tables** VA 0x781760 (slot 2), 0x781410 (slot 3), 0x781230 (slot 4): rows of 4 x i16 `(x0, 0, x1, h)`, row k = cell k; row 104 of 0x781410 repeats
   cell 103 (`4017, 0, 4056, 39`); the terminators are `0, 0, 0, 0` / `-1 x 4`. Dumped in `tables.txt`; checked by a Data test against the raw eboot.
3. **Which mark, when** (HUD VA 0x54CD7..0x54F94 and helper 0x53630): the alpha 0xDF08E4 must be > 0 and the anchor valid (`x >= 0 or y > 0`); window index
   (F1105, F1109 in English) > 2 -> the bubble mark (slot 4) at `(x - 2, y + msg_y + 2)`; else F822 == 1 -> `0x53630(F799, x - 57 (English) - 3.7, y + msg_y + 4.3,
   alpha x fade)`, which draws slot 3 at half alpha when F799 == 1 and slot 2 at full alpha otherwise; else (F822 != 1) slot 3 at `(x + 115, y + msg_y + 2)`,
   half alpha. Auto mode (0x17DB230 bit 0) returns before any draw on all three paths. The end mode decides whether a mark exists at all: only mode 0 sets wait
   bit 0x400 (`@n`, `@e` and the page option's no-click messages show nothing); F799 (`_WNTY`) decides line or page.
4. **Alpha** (VA 0x53F8B..0x5400C): while the window fade 0xDF0730 > 0, `0xCA690(block slot+4, 0x30, &x, &y, head, tail)`; if it reports the text complete and
   E00 & 0x400: `alpha = min(alpha + 0.1, 1)` (0.1 at 0x1A70DC), else `alpha = 0`. Emulated: 0.1, 0.2, ... 1.0 in frames 0..9, then 1.0; 0 with 0x400 clear; 0 with
   the head on a middle glyph; still rising in auto mode (nothing drawn). The HUD runs after Adv_Update and tick_reveal, so the mark appears in the reveal frame
   and goes in the advance frame.
5. **Anchor, VA 0xCA690** (`f_ca690.asm`): line origins as the block draw's (6.1) with x = 88 (VA 0x2D3048, eight copies at 0x2D3460) and y = 0; one pass over
   the records: zeroed control records skipped; a record above the head -> alpha 0; else alpha 1 when `tail > ctr` or `head - tail <= 0`, else
   `(head - ctr) / (head - tail)`; ruby records count for the alpha, not the position; plain glyph `x = (x2 - x0) * sx + (dx + x_line) + 3` (0xCAB6E..0xCABA0,
   3.0 at 0x2D3058), `@b` glyph `x = MirrorX - dx - w' * sx + x_line - 16` (0xCAC14..0xCACAA; MirrorX 463 / 565 at 0x2D3270); `y = dy + y_line`; both truncated
   (`vcvttss2si`); result = the last record's alpha == 1. `$000003` en: trunc(88 + 79.4267 + 26 x 0.24667 + 3) = 176, y 26; ja: 307, 0 (records in the golden file).
6. **Stored position** (VA 0x54B61..0x54B80, 0x54CB1..0x54CD7): `x = trunc(x + origin_x - (87 if window or F1111 >= 3 else the page origin x))` — 0 for the page,
   `origin_x - 87` for a bubble (window 5: 213.5 - 87 -> 245 becomes 371; found when the bubble scenario did not match the plain rule, `bubble_probe.py` shows
   the HUD lays nothing out again); with F822 != 1 the origin code is skipped (0x54A37 -> 0x54BD8, origin 169.333 / 43.1407 at 0x1A7154 / 0x1A7158) and x stays.
   `0xDF088C = float(x)`, `0xDF0890 = y + msg_y` (the value the choice screen reads, system_flow.md 5.3; K8 used it already).
7. **Animation**: one counter VA 0x78122C (-1 in the data segment) for all marks, advanced by the frame delta (0xD47C0) only while a mark is drawn, modulo
   2 x cells (118 / 210), row = counter / 2: two frames per cell, no blink or bob; the next mark carries on from where the last stopped. Emulated ticks
   0, 1, 2, ... with cells 0, 0, 1, 1, 2, 2, ...
8. **Draw**: `TexDrawRect(slot, 0x10, 0, &row, x, y)` (0xEB890 -> 0xDF760) after `colour(alpha x fade x factor, 1, 1, 1)` (0xD9D20) and the picture scale
   (0.333, 0.333) (0xD9DD0), into list 0x1E (3.0 x 3.1339 px per unit, the page's quake offsets, the list alpha fade x 2 max(0, T - 0.5) x HUD alpha: the mark
   fades with the fade squared). Emulated pixel quads: en line / page mark (345.9, 204.646)-(384.861, 245.346) = 38.96 x 40.70 px; ja (909.9, 167.038);
   bubble (1107.0, 854.0)-(1149.957, 902.001) = 42.96 x 48.01 px; F822 != 1 (873, 952.95) (the list offset 302.8148 of the bottom window).

PS4 vs Switch (knife `game.rs` 5620..5665): knife draws the line icon at the pen + (2, 3.5), the page icon at (2, 5.5) and the bubble icon at (4, 4) at 0.36 x 0.45
units per texel with its own pen rule; the PS4 anchors on 0xCA690's last glyph with the offsets of item 3 and 0.333 per texel. knife's two-tick animation and the
"page icon repeats cell 103" note agree with the PS4 tables. knife hides the icon in auto mode and during a rewind; the PS4 code tests auto only (the HUD does not
run while the rewind holds the frame).

## 4. The mode icon (auto / skip indicator): none on the PS4

`f_564a0.asm`: the banner draw VA 0x564A0 (called by the HUD draw 0x57550) draws DISP_PARTS child 10 ("Autosaving / Quicksaving / Auto / Skip" rows, 432 x
264) through three banner slots 0xDF0EF4 / 0xDF0EF8 / 0xDF0EFC with timers 0xDF0F00 / 04 / 08: `0x562D0(k)` raises slot k (k >= 3 clears all), `0x56300`
(from 0x599C2) ticks them (0.04 per frame at 0x1A7DC0, up to 7.0 at 0x1A71E0, then 1.0 falling to 0), the draw scales the row with the nine keys at 0x781AC0
(`t x 9` through 0xCD670) and the rows 0x781B10 / 0x781B18 / 0x781B20 at (-10, 50) / (2000, 2000) / (-10, 65) (0x1A7200..0x1A720C). The callers of 0x562D0
(`Index.callers`): 0x61BB2 in 0x60710 (the ADV input function: the quick-save action) and 0x6F250 in 0x6EB60 (from 0x609F7, the same action) pass k = 0 -> row
`8, 72, 424, 128` = "Quicksaving"; 0x6D4DC / 0x6D57F / 0x6D8C0 in the save functions 0x6D450 / 0x6D540 / 0x6D600 pass k = 1 -> row `0, 0, 1, 1` at (2000, 2000): a
1 x 1 texel off screen, a disabled "Autosaving". No caller passes k = 2 (row `8, 136, 424, 192` = "Auto"), and no row spells "Skip". So the PS4 shows a banner
only for the quick save; auto and skip are shown only while the mode panel is open (0x56740 draws child 5, the ◀◀ ◀ ▶ ▶▶ buttons). The port's Auto / Skip
banners (`Tsuki.Ui/Framework/UiBanner.cs`, knife's Switch behaviour) are therefore a deliberate deviation left in place for the lead to decide; the same
function, keys and timing are what the PS4 uses for "Quicksaving" (its position (-10, 50) and the rows differ from knife's (0, 32); not changed here).

## 7. Open issues

1. **F822 != 1 pages**: the PS4 draws the message and its mark at the bottom-window origin (169.333, 43.1407) with the list offset 302.8148 (text_vertical_scale.md 3);
   the port's `DrawPage` keeps the page origin for F822 != 1 (not used by story scripts, textbox.md 7). The mark follows the port's own origin there; only the
   x + 115 / half-alpha rule is the PS4's. Not reached in play.
2. **Mode banners**: the Auto / Skip banners are knife's; the PS4 shows only "Quicksaving" (section 4). The lead decides whether to keep them.
3. The **second window** F1111..F1113 (K3 item 8) is still not drawn; the mark's `F1111 >= 3` branch of the x shift is implemented but untested in play.
4. The icon's alpha carries over when an advance and a complete new message fall into one frame (fast-forward: 0.2 for a frame), as the PS4 code does; a
   paced player never sees it.
5. The screenshots are of this port, not of the console; a PS4 capture (docs/status/ps4_captures.md) would confirm the moon's phase timing and the half alpha
   of the page mark. The frame-table repeat of cell 103 and every position constant are read from the eboot, not inferred.
