## 1. Verdict on K38

**K38's root cause is right and its fix works.** Reproduced on v0.1.2 (run `head_repro_en`): GALLERY, Flowchart, a node replays, Esc, FlowChart, "Do you want to
return to the flowchart?", Yes: 60 frames later the stack is `[SystemMenuScreen]` with `story False` (`r05_after_yes.png`: the menu over its backdrop, no scene);
after Esc `ui Story []`, `story False` for good, Decide / Esc / right click do nothing (`r07_later.png`: black). Exit 0, no crash.log: a dead screen, not a crash. The
same script on K38's build (`fix_repro_en`) is back on the gallery's chart (`[TitleScreen>GalleryScreen>FlowchartScreen]`) 60 frames after Yes.

The diff reads correctly: the menu leaves (fade 1/30 a frame, no input) and only then clears the stack and calls `EndReplay`; `EndReplay` ends the story and leaves a
pending gallery return that the runtime applies once no screen is open, in the same step; `UiRoot.Clear` empties the stack before it calls the `OnClosed`s (a nested
`Clear` is harmless); the last-resort title never fired in any run here (no `nothing on screen` line in 27 run logs, the soak included); the error-box path hides
a window that exists (`_window` is disposed only after the catch). K38 missed three bugs on the same paths; all three were already in v0.1.2 and are fixed here
(section 2).
