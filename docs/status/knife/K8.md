## 5. Soft clip insets and rotated windows (script.md 4.3a, layers.md 9, knife `ClipRect`)

**Panel geometry** (the question of the brief): the window of a layer with a crop is its crop rectangle in 1920 x 1080 pixels (STCH a12..a15, moved by the layer's shakes and the screen shock), cut to the frame for the scissor; the stage's drawn
records equal the engine's (K2's differential tests, unchanged and green in the Data run). The prologue panel `_STCH(17,img1688,266,82,1000,255,518,,CC,,,,160,-285,888,1650,90,0)` is read back in
`SoftClipOnRealScenesTests`: crop (160, -285, 888, 1650), a16 = 90, a17 = 0, scissor (160, 0, 888, 1080). The geometry was right; what was missing is the edge.

**What the arguments mean** (a16 = inset in pixels, a17 = mode; in the 549 scripts 2,035 STCH / SCH2 statements have a16 > 0 (mostly 15 / 30 / 60 / 90 / 120): a17 = 0 in 1,779, 1 in 206, 7 in 36, 2 in 14): knife's reading of the same engine,
checked against the PS4 where the PS4 has a counterpart: **modes other than 1..6** mask the window with a rounded rectangle whose edges fade out over (inset rounded up to even) px (twice that in mode 7, with the sharper `_2` textures), at most half the
window's extent; a side that lies off the screen, or a window as wide as the frame, gets no fade there; the profile is the BORDER_PARTS gradation texture (allpac3 `BORDER_PARTS`: children 0..5 = 20 / 64 / 80 / 128 / 256 / 512 texels, 6..11 inverse, 13..18 the `_2` set;
class = first of the six radii read from the eboot (10, 32, 40, 64, 128, 256; K1b `SoftClipRadii`) above the radius in 960 units). **Modes 1..6** shrink the scissor by the inset on every side whose extent is under the screen and draw a ridge of the mode's colour
(black, white, red, three tints) that fades inward from the shrunk edge.

**Change**: `Stage/StageDraw.Clip.cs` (MPL header, listed in THIRD_PARTY.md; ported from knife `ClipRect::inset_rect / soft / band`, unrotated branches): `ClipWindow`, `SoftOf`, `AddSoftMask` (nine pieces of the gradation texture and the inner fill into render target 8, effect 58),
`AddBand`; `StageDraw.cs` (`ClipOf` keeps the unclipped rectangle plus a16 / a17, `DrawLayer(..., soft)`: the window layer's quads are multiplied by target 8, and the silhouette mask of the layers it holds is narrowed by the same pieces
(`MaskMultiply`); the ridge is drawn after the window and what it holds); `IEbootTables.ClipRadii` (default member; `GameEbootTables` reads the eboot table). **No renderer change**: the existing mask target, `QuadFx.Masked`, effect 58 and `MaskMultiply` carry it.

**Rotated windows**: not drawn, deliberately. knife turns a clip by its ROT2 word (STRR). On the PS4 STRR / STCH a19 write the angle field +0x15C that **no draw code reads** (layers.md 9, 13 item 3, 954 [E]), so a PS4 window never turns.
(PS4 vs Switch, below.)

## 6. Hitches (K6 issue 6, K7 D1)

**Instrumentation** (verification mode, kept): per step `AppRuntime.LastTimes` (movies, menus, story, media commands, end of story, UI draw), per frame the feeder wait with the tiles requested and named, execute and present, `SlowStatement`
(a statement that takes 5 ms or more); the `hitch ... ms` and `slow step` lines and the summary (`frames: N, longest, over 33 ms / 50 ms after the first second`, `texture holds`).

**Causes found** (paced, hidden, fresh profile, release build, 9,000 steps of `--autoplay skip --choices first`, virtual movies, `scratch/K8/hitch_before2.log`): 35 of 41 frames over 33 ms were `feed`: the main thread waiting for the tiles of a new scene
(up to 121 ms, 3,300 ms in all over 218 frames), mostly the **graded** tiles (`/grade17`, `/grade19` ... each STEC key is its own texture set); the others: opening a movie on the main thread (425 ms at the prologue movie, `media`), decoding a script (28..37 ms
at script switches), decoding UI sheets to learn their size or tile layout (20..100 ms at the first choice, the title screen's first draw 53 ms: `uidraw`), first use of the interpreter, text layout and the motion table (`_ZM` 20 ms, `_STGS` 32 ms, `_FADS` 12 ms), and the GPU taking the uploads at the next swap (`present` 44..116 ms right after a 200-tile frame).

**Changes**:

| cause | change |
|---|---|
| movie open on the main thread | `MovieHost.Open` opens the player on a thread of its own (FFmpeg load included); until it is ready the slot reports a movie that is not playing and not ended; a missing file still fails at once; `Player()` / `IsOpening()` |
| script decode at a switch | the app's `ScriptCache` is thread-safe and, the first time a script is used, decodes on a worker the scripts its `_JUMP` statements lead to (and their label tables) |
| sheet decode for a size or layout | `IGameData.UiSheetSize` / `UiSheetLayout` (default members; `GameFolderSource` reads the image header: `ImageMzp.ToLayoutPicture`); `GameHost` (message window, choice decoration) and `UiAssets.Geometry` use them |
| tiles of the next scene | **look-ahead**: `GameHost.LookAhead` reads up to 400 statements or 10 messages ahead of the interpreter, `StageRuntime.LookAheadScan` keeps a picture and a colour grade per layer (STCH / SCH2 with variant digits and `src`, STEC, SNX2, SNX3, STCC, the commit at `_FADS`) and names the tiles with the grade key the stage will give them; the app hands them to `TextureFeeder.Prefetch`; the decode workers take them **behind** every tile a frame waits for (`DecodeWorkers.EnqueueBackground`, `Promote`) and the upload scheduler uploads 4 MiB of them per slice behind the urgent tiles (`UploadScheduler.EnqueueBackground`, `Promote`); a frame that names one moves it to the front |
| waiting for tiles | in paced play the main thread no longer waits for tiles: the frame is held (the previous picture stays, the loop polls and uploads the next slice, the logic does not step) until its tiles are resident; `--fast` and every run that takes screenshots still wait, so their pictures are complete |
| first use | a scratch host runs the first story scene in the background thread while the notice and the title are up (interpreter, stage, text layout, tables, picture layouts); not in `--fast` |

## 9. PS4 vs Switch

* Choice: x 30 / 87 and width 574 / 474 (PS4, VA 0xA6E10, 0x9B6F9) against knife's 32 / 88 and 566 / 466; the first line from the click icon like knife's `page.pen`, but with the PS4's fixed pitch 26.02 and the canvas 640 x 344.7.
