# K37: review of K36 (the per-character voice rows of Config > Sound)

Package K37 (label `k37`), run on 2026-11-01 on top of commit 59380ca (v0.1.1) with K36's uncommitted tree. Nothing is committed. Builds in
`artifacts/k37` (`-warnaserror`, 0 warnings); the v0.1.1 program used for the old-save check was built from `git archive 59380ca` into
`scratch/k37/v011` (its own copy of the FFmpeg DLLs) with `--artifacts-path artifacts/k37_v011`. Every game run hidden and muted (`--hidden --mute
--fast`, `SDL_AUDIO_DRIVER=dummy`, BelowNormal priority) on its own `--save-dir` under `scratch/k37/`; the game folder, `%APPDATA%\Tsuki`,
`%APPDATA%\shadPS4`, `artifacts/play*`, `artifacts/dist`, `D:/TsukihimePort-public` and `D:/TsukihimePort-release` were not touched. No PowerShell
with Add-Type, DllImport, P/Invoke, LoadLibrary, base64 or Invoke-Expression; the two scratch scripts are read-only Python from `.venv`
(`scratch/k37/read_marks.py`, `readmax_dump.py`: they print a save file's marks, readmax entries and character volumes).

## 1. Verdict

K36 is correct. The three rules it decoded (the `_VPLY` marks, the row list, the test button with `Sound_ApplyConfig(0)`) re-derive from the
eboot exactly as written; the port's code follows them; the hidden runs in all four languages show the rows after the prologue, a slider changing
that character's voice gain (the scene voice and the test voice alike), the marks and the volumes surviving a restart, and a save written by the
real v0.1.1 program getting its rows rebuilt at start with the same set the marks produce. One small deviation found and fixed (section 5): the
PS4 forgets the test row at the start of every Test press (0x401E9), the port only on success.

## 2. The diff, read critically

`git diff 59380ca` (12 files, +300 / -24) plus the new `VoiceMarks.cs`, the six test files and K36.md. Checked line by line against the
disassembly of section 3:

- `VoiceMarks.Note`: `G[73] |= (ushort)(1 << (c & 31))` is the `shl edx, cl; or word ptr [0x164C6B2], dx` of 0x99F06; the return for character 23
  or a negative entry, `slot = log2(mask[c < 24 ? c : 0])`, `G[31 + k] = (u16)entry`, `G[words[k]] |= 4` are 0x3D266..0x3D2A6. The heard bit is
  written before the two early returns, as the handler does (the bit at 0x99F08, the call at 0x9A058).
- `GameHost.DispatchSound`: the marks after every `_VPLY` / `_VPL2` outside scan mode, with `Sound.VplyEntry` (the pending entry after the
  underscore rule, -1 when a `_name` found none) and `Sound.PendingVoiceCharacter` (0x1654208). The scan gate is 0x968B2 (`cmp byte [0x174DE48], 0;
  jne`), before the name is even stored, so the marks must not be written in scan mode: correct.
- `ConfigScreen.BuildVoiceRows`: bit 4 shows, rows 15 / 16 face 18 unless bit 1, rows outside 0x430C9 name 19 unless bit 2, Shiki's row by the
  script word in a story and by nodes 485 / 1 from the title: all as 0x3DF20 (section 3.2). The port's `Script` is `_vm.Image.Index`, the script
  number whose allscr section is `script + 3` (script.md 2.1), the same numbering as the PS4's word 0x86AA18 (adv_state.md 2, "+0x18 script").
- `AppServices.PlayTestVoice` / `SoundModel.StartTestVoice` / `ApplyTestRow` / `SetVoiceVolume`: 0x401E0, 0x3EA25..0x3EA89 and 0xB6F0 (section 3.3,
  3.4); the one difference is the test-row reset of 0x401E9 (fixed, section 5).
- `AppServices` constructor: the rebuild runs on the `Vars` the host is then built on, and the capture + commit happen after the host exists, so
  the marks are in the live profile, in the system block and (with a save file) on disk before the first frame. `Commit()` returns true without
  writing under `--no-save`.
- `VoiceMarks.RebuildFromReadText`: a `_Z` marker counts as read when `readmax[block] != 0 && sub <= readmax[block]` (`SystemData.IsRead`, the
  0x75C90 rule), and the engine raises `readmax` only when the marker after one is reached (`MarkerState.Enter`), so a credited `_VPLY` ran before a
  marker the player left. The entry rules (`_name` repeats the pending one, a `_ZM` consumes it, a `_VPL2` consumes it) match `CmdVply` / `VoiceGate`.
  The deviation K36 states (G[31 + k] = the last entry in script order) is real and harmless.
- `ReplayVoice` now uses `Host.Sound.PendingVoiceCharacter`: consistent with the gate, which reads 0x1654208 and never clears it; not re-derived
  from the replay key's own code (open point 7.1).
- Nothing in the diff touches `MarkerState`, the save layout or the mixer; the per-character gain reached the mixer before K36 (`VoiceGate`,
  `char_vol[k] * voice / 100` into byte 0xD, the play call at `byte * 0.01`), only the rows were missing.

## 3. Rules re-derived from the eboot (`tools/eboot/disasm.py`, my own reading)

1. **0x3D260** (callers: 0x9A058 only): `cmp edi, 0x17; je ret` (character 23); `test esi, esi; js ret` (negative entry); `cmp edi, 0x18; cmovb eax,
   edi` (else 0); `log2f([0x86A850 + eax*4])`; `mov word ptr [0x164C620 + rax*2 + 0x3E], bx` = G[31 + k] = entry; `mov eax, [0x1A6850 + rax*4]; or
   byte ptr [0x164C620 + rax*2], 4` = G[words[k]] |= 4. **0x99EF7..0x99F08**: `ecx = [group + 8]` (the character), `[0x1654208] = cx`, `edx = 1 << cl`,
   `or word ptr [0x164C6B2], dx` = G[73] |= (u16)(1 << c). **0x9A022..0x9A058**: name byte 0 == '_' -> `esi = [0x16541FC]` (the pending entry) else
   the hex parse (0x76C10) into 0x16541FC / 0x1654200 / 0x1654204; `edi = (i16)[0x1654208]; call 0x3D260`. Agrees with K36 rule 1.
2. **0x3DF20** (caller 0x3E69B): for rbx = 0..18, `rsi = 5 rbx + 100` (the row's volume item) must lie in [[0x66F260], [0x66F264]] and be found in
   the page's layout rows (0x3DFE0..0x3E02F), else the row is disabled; `al = G[[0x1A6850 + rbx*4]]`, `test al, 4; jne 0x3E0D0` else disabled
   (0x3E08C..0x3E0C7: layout zeroed, item -1). Shown: `0x3D510(1, (i16)cfg[0x76 + 2 rbx])` (the volume item), `ldexpf(1, rbx)` and `test
   cfg[0x3C], eax; sete dl` (the mute item), y from the shown count [0xDDB514] (0x3E125..0x3E1AC), count++ at 0x3E254. Face (0x3E136): `lea eax, [rbx -
   0xF]; cmp eax, 1; ja` -> rows 15 / 16 take 18 unless `test byte ptr [G[w]], 1`; other rows their own number; row 0 branches at 0x3E2CD. Name
   (0x3E223): `mov eax, 0x430C9; bt rax, rbx; jb` -> own number; else 19 unless `test byte ptr [G[w]], 2`; row 0 branches at 0x3E285. Row 0 in a
   story (`[0xE20CC8] != 0`): `F[23]` (`word ptr [0x164B1D0 + 0x2E]`) == 0 -> -1 (hidden); script word [0x86AA18]: face 19 when == 1 (0x3E30D), 18
   when `& ~1 == 2` (0x3E418), else 0; name 19 when `& ~1 == 2` (0x3E2B4), else 0. From the title: `0xB81A0(0x1E5)` false -> face 18 (0x3E452), name
   19 (0x3E3D0); true -> name 0 (0x3E338), face 0 when `0xB81A0(1)` (0x3E3A3) else 19 (0x3E45E). 0x3DF20 reads no config byte but +0x76 and +0x3C:
   Play All Voices plays no part. Agrees with K36 rule 2 and with `BuildVoiceRows`. One imprecision in K36's wording: the range check is on the
   row's volume item 100 + 5r alone (`lea rsi, [rbx + rbx*4 + 0x64]`), and the layout search then finds that item among the page's rows; the port
   models neither (its rows are the 19 of page 1), so nothing follows from it.
3. **0x401E0** (caller 0x3FF9D): `[0x66C720] = -1` **first** (0x401E9); `cmp word ptr G[[0x1A6850 + r*4]], 0; je ret`; `movzx eax, word ptr G[31 +
   r]; test ax, ax; jle ret`; `[0x66C720] = r`; `VoiceRequest(G[31 + r], -1)` (jmp 0xC3A80). K36 rule 3 has everything but the first store: the
   port's `PlayTestVoice` returned early without touching `_testRow`. Fixed (section 5). **0x3F941** (in the config's open 0x3F870): `[0x66C720] = -1`,
   as K36 says.
4. **0x3E9B0** (`Sound_ApplyConfig(full)`): full != 0 -> byte 0xC = (1 - cfg[0xA6]) * cfg[0x14]; then 0x674B0, bytes 0xB / 0xE / 0xF; full != 0 -> byte
   0xD = cfg[0x16] and return (0x3EA19). full == 0 (0x3EA25): `edi = [0x66C720]; js ret`; `ldexpf(1, row)`, `test cfg[0x3C], eax; jne` else `call
   0x8EA0` (stop the voice); `ecx = (i16)cfg[0x76 + 2 row] * (i16)cfg[0x16]`, `/ 100` (the 0x51EB851F, sar 0x25 sequence), `jmp 0xB6F0`. **0xB6F0**:
   `[0x17DA268 + 0xD] = dil`; the voice record at `0xDD8B20 + counter * 0x34`; state 0 -> return; `v = trunc((i8)gain * record[+0xC] * 0.01)`,
   clamped to 0..100 (`andn`, `cmovb`); `vtable[0xA8](stream = counter + 2, v * 0.01)`. Agrees with K36 rule 3 / 4, `ApplyTestRow` and `SetVoiceVolume`.
5. **0x3EAC0** (the config defaults): `movabs rax, 0x3200320032` written over the character volumes: every row starts at 50 %, not the 40 % of the
   music and SFX sliders (`ConfigBlock.CreateBootDefaults` sets 50 for all 19). The issue's "40 %" was the music default.

PS4 vs Switch: nothing new; 0x430C9 is the complement of knife's 0x3CF36 within 19 bits, as K36 found.

## 5. Fix

`src/Tsuki.App/Services/AppServices.System.cs`, `PlayTestVoice`: `_testRow = -1` before the checks, as 0x401E9 does before 0x401FE / 0x4020F. Before,
a Test press that played nothing (a row whose word is 0, or whose last voice is 0 or reads negative as i16) left the previously tested row as the
test row, so that row's slider went on moving the voice still playing; the PS4 stops following it. Reachable only through a last voice of entry 0
(or >= 32768), so no player would have seen it; the fix keeps the port exact. Test: `VoiceRowsAppTests.AVoicedLineLeavesTheMarksAndTheTestPlaysTheRowsVoiceAtItsVolume`
now presses a dead Test (Shiki's row before his first line) while Arcueid's test voice plays and checks that her slider no longer commands a volume
change, and that a new Test on her row follows again.

## 7. Open points

1. The replay voice's character (`ReplayVoice` now takes `PendingVoiceCharacter`) was not re-derived from the eboot: the rip-relative readers of
   0x86AA28 are the `_ZM` handler (0x92836, 0x928E5, 0x92E93: the "a voice exists" flag) and two resets (0x605DB, 0xA326F); the replay key's reader
   was not located in the time of this review. The port's choice is the gate's own character word, which the gate never clears, and the synthetic
   test covers it.
2. The Japanese run's scrolled screenshot (`ja_rows.png`) is the unscrolled view (`wheel=6` scrolls up); the English and both Chinese runs have
   the scrolled rows (`en_rows_a.png`, `zc_rows_scrolled.png`, `zt_rows_scrolled.png`), and K36's `scratch/k36/shots/sound_ja_rows.png` the Japanese one.
3. Autoplay reaches a different point by step 5600 on a profile that already has a save file (scene 304 instead of 303): a verification-mode
   detail, not K36's.
4. K36's open points 1..4 stand; none affects the player.
