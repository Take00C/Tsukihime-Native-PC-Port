# K17: the launcher (TsukiLauncher.exe)

Package K17, run on 2026-10-27. A WPF launcher in a TYPE-MOON / "blue glass moon" look: sidebar with seven pages, a hero banner with the game's own title art, a ready check, quick
settings and a big PLAY button. Nothing is committed. Every number below comes from a command run in this session. All checks used a temporary profile folder (`--data`, a temp
`LauncherPaths`), builds in `artifacts/K17`, offscreen renders only (no window was ever shown); `artifacts/play*`, `artifacts/dist`, the user's `%APPDATA%\Tsuki`, the game folder
(read-only) and `%APPDATA%\shadPS4` (enumerated only) were not written.

Decisions worth knowing:

* **Version 01.01.** The folder's `param.sfo` says `APP_VER 01.00` (a known disagreement, RUNTIME_REQUIREMENTS 3.3 item 4). The build is identified by the eboot hash, so an accepted folder
  shows "01.01" (`GameFolderCheck.AnalysedVersion`) and the Game files page adds "(param.sfo says 01.00)"; an unaccepted folder shows param.sfo's value.
* **Logo instead of the serif title when the art is there.** The game's logo cell already carries the wordmark and the subtitle; drawing the serif "TSUKIHIME" and "-A piece of blue glass moon-" beside it
  duplicated both. The serif title and italic subtitle are the fallback (no folder, or art that cannot be read). The gold overline and the chips are in both states.
* **PLAY is never disabled**, it explains: an unready folder opens the Game files page with a message.

## 3. settings.ini as the game reads it

`prompts` (K9), `fullscreen on|off`, `language ja|en|zc|zt`, `window WxH` (640 x 360 .. 16384), `monitor x,y`, `vsync on|off`; documented in README. The game reads the file once, before the window exists.

* `window`, `vsync`: window options. `monitor`: the display whose top-left corner is that point (SDL bounds = Windows rectangles, both per-monitor DPI aware; a corner that matches no display is ignored); the window is moved there and centred
  **before** any fullscreen request, because borderless fullscreen uses the display the window is on (with `--fullscreen` and a monitor the request waits for the move).
* `fullscreen`, `language` are **one-shot**: applied to the config block (language unless `--lang` was given; window mode byte 0xA9, the byte Alt+Enter and F11 already keep) and removed from the file, so the config screen and Alt+Enter keep the last word and the
  launcher shows the pending key, else what `save.dat` says. This keeps the hooks to the start of the program: no write-back code in the game's loop.

## 5. Open issues

1. The visible window was never opened (rule: nothing on the user's screen): the chrome buttons, dragging, maximise (the content gets the resize-border margin), the folder and file dialogs, the minimise-while-playing and restore-on-exit behaviour,
   and the fade of the page change are code-checked and the visual tree is rendered, but not clicked. The first real run should look at them.
2. Monitor placement and fullscreen-on-the-second-monitor ran only against the one display of this machine (the SDL placement test and the unit rules); the corner-matching logic is covered, a second monitor is not.
3. Controller names: the code path with a pad was not run (none connected). The names come from the registry key Windows keeps per VID / PID (`...\MediaProperties\PrivateProperties\Joystick\OEM`), else the winmm product name.
4. `vsync=off` and the window size are read by the game and applied by SDL / the window options (unit + SDL smoke test); no frame-time comparison was made.
5. The ready check names the graphics adapter from the registry (no WMI package in the tree) and cannot test OpenGL 3.3 itself: the game does that at start, and the row says so.
6. Volumes and the scaling filter are not in the launcher (reasons in section 1). If `Tsuki.Render` gets a present-filter property later, one more setting row and one more key (`filter=smooth|sharp`) would do it.
7. `Tsuki.App.exe` in the launcher's build output is a copy made by the build; a build of the game alone does not update it until the launcher project is built again (`dotnet build src/Tsuki.slnx` does both).
