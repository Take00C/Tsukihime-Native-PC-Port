# K20: the port's identity on Windows (icon, localized title, Tsukihime.exe, shortcuts, Japanese dialog buttons)

Package K20, run on 2026-10-30 on top of commit 1eb9775. The user's requests: an icon like PC visual novels have, a window title that follows the game language, the full
name "Tsukihime" on the programs, a game executable that starts without the launcher, a desktop-shortcut action in the launcher, and the quit question's Yes / No in
Japanese. Nothing is committed. Builds in `artifacts/k20` (Release, `-warnaserror`, 0 warnings), the publish in `scratch/k20/pub` (`artifacts/k20pub`), every game run hidden and
muted on its own `--save-dir` under `scratch/k20/`, except the two visible checks of section 7 (a few seconds each, muted, their own profiles). `artifacts/play*`,
`artifacts/dist`, the user's `%APPDATA%\Tsuki`, the real desktop and Start menu, and the game folder (read-only) were not touched. No knife file was translated;
`docs/THIRD_PARTY.md` only renames the program.

## 1. The icon (original art)

`tools/setup/make_icon.py` (Pillow, from `.venv`) draws every size on its own at 4..128 x supersampling and reduces it with Lanczos: a deep indigo (#0A0F24 -> #0E1532) rounded
square with a thin #8FA6FF border, a crescent (a disc less an offset disc, the launcher's own proportions) filled #9CD2FF -> #5E8BFF with a soft moon-blue glow behind it, and a
four-point sparkle in the bite. It writes `assets/icon/tsukihime.ico` (16, 20, 24, 32, 40, 48, 64, 96, 128 as 32-bit BMP entries, 256 as a PNG entry; 180 KB), `tsukihime_256.png`,
`tsukihime_16/32/48.png` (for looking) and `tsukihime_64.rgba` (16 KB of straight RGBA, embedded in the game). Pictures read: `scratch/k20/icon_sheet.png` (16, 32, 48 enlarged beside
the 256) and `icon_1to1_x3.png` (every size on white and on dark): the crescent reads at 16 px as a two-tone moon on the plate, the sparkle is a bright dot there and a star from
32 px up; no size is a resized copy of another. No game material is involved.

Where it is used:

* `ApplicationIcon` of `src/Tsuki.App` and `src/Tsuki.Launcher`: both executables carry icon group 32512 with the ten RT_ICON entries (checked with `FindResourceW` on the built and on
  the published exes; `Icon.ExtractAssociatedIcon` of Tsukihime.exe gives the 32 px frame).
* The launcher window: `MainWindow.xaml` `Icon="/Assets/tsukihime.ico"` (the .ico is a WPF `Resource`; WPF picks the 16 and 32 px frames); the drawn `MoonIcon` is the fallback. The
  offscreen render's `window_ok.txt` says `window Tsukihime Launcher, min 960 x 600, icon True, chrome True`.
* The game window: `GameWindow.Create` sets SDL's `SDL_WINDOWS_INTRESOURCE_ICON` hint to `WindowOptions.IconResource` (= `GameWindow.ApplicationIconResource` 32512) before the
  video subsystem registers the window class, so the class icon is the executable's own group and Windows picks the right size for the title bar and the taskbar (no scaled
  bitmap). When the process is not Tsukihime.exe (`dotnet`, a test host: `GameWindow.ExecutableHasApplicationIcon()` false), `GameApp.ApplyWindowIcon` hands the embedded 64 px RGBA
  (`AppIdentity.EmbeddedIcon`, resource `Tsuki.App.Icon64.rgba`) to the new `GameWindow.SetIcon` (`SDL_CreateSurfaceFrom` + `SDL_SetWindowIcon`). The log says which:
  `window icon: the executable's icon group` in every real run here.

## 2. The window title follows the language

`ParamSfo` moved from the launcher to `Tsuki.Data` (same code; `TryRead` now reads through a `FileStream` capped at 1 MiB, because Tsuki.Data may not read a file whole), and
`GameFolderSource.ParamSfo` / `Title(language)` read `sce_sys/param.sfo` of the open folder once. `GameTitles` maps the PS4 language numbers: `TITLE_00` Japanese, `TITLE_01`
English (the retail file has none, so English takes the plain `TITLE`), `TITLE_11` Simplified Chinese, `TITLE_10` Traditional Chinese; fallbacks ja 月姫 -A piece of blue glass
moon-, en TSUKIHIME -A piece of blue glass moon-, zc / zt 月姬 -A piece of blue glass moon-; a blank key counts as missing and the Asian languages never fall back to the English line.
The user's file (`scratch/k20/param_sfo.json`, read-only): `TITLE` "TSUKIHIME A piece of blue glass moon", `TITLE_00` "月姫 -A piece of blue glass moon-", `TITLE_10` = `TITLE_11`
"月姬 -A piece of blue glass moon-".

`GameApp`: the window is created with the fallback title of the start-up language, retitled from param.sfo once the folder is open, then from the profile's language when the
services exist, and `_services.HostReplaced` (the host is rebuilt on a language change) retitles it at once; `window title: ...` is logged each time (the hidden runs check it).
`WindowOptions.Title` defaults to "Tsukihime"; nothing the player sees says "Tsuki" alone any more (the window, the message boxes, the folder dialog, the usage line, the
launcher's captions; the `%APPDATA%\Tsuki` folder keeps its name so existing saves keep working, and the README says so).

## 3. Tsukihime.exe and TsukihimeLauncher.exe

`AssemblyName` Tsukihime (project, namespace and folder stay Tsuki.App) and TsukihimeLauncher (Tsuki.Launcher); `Product` "Tsukihime PC port", `AssemblyTitle` on both. Updated:
`GameLauncher.AppFileName` ("Tsukihime.exe"; `IsGameRunning` looks for that process), new `LauncherFileName` / `FindLauncher`, the launcher's copy and publish targets
(`TsukihimeLauncher.*`, the published `Tsukihime.xml`), `app.manifest`, the mutex names (`Local\Tsukihime.<hash of the profile folder>`, `Local\TsukihimeLauncher`), the usage
lines, the stderr lines, `PlayerMessage` ("next to Tsukihime.exe"), the tests, `tests/Tsuki.Tests.Render/Smoke/pick_folder_roundtrip.ps1`, README, `docs/THIRD_PARTY.md` and the
FFmpeg source notice. The status files K6..K19 keep the name of their time (the README says so under the verification command).

**Direct start.** `Tsukihime.exe` started by itself uses `--game`, else `TSUKI_GAME_DIR`, else the remembered `game_dir.txt`, else asks. The remembered file now lives in the
profile folder (`--save-dir`, else `%APPDATA%\Tsuki`, the same place the launcher's `--data` profile keeps it); before, a verification run on its own `--save-dir` still took the
user's folder. The first run without a folder shows a message box in the start-up language ("Tsukihime needs your own copy of the PS4 game. In the next window, choose the extracted
CUSA47999 folder (the one that holds eboot.bin and image\). The folder is only read; nothing in it is ever changed." and its ja / zc / zt forms), then the folder dialog with a
localized caption (`FolderDialog.Show(parent, location, title)` through `SDL_ShowFileDialogWithProperties`), and a wrong folder says so in the same language. The start-up language
(`AppIdentity.StartupLanguage`): `--lang`, else the launcher's pending `language=` line, else the profile's config block (save.dat is now read before the folder is looked for),
else the Windows display language mapped to one of the four (`PortText.FromCultureName`).

## 4. Shortcuts in the launcher

`Core/Shortcuts.cs`: `IShellLinkW` + `IPersistFile` through `[ComImport]` (no package), `Create(spec)` and `Read(path)`; `Shortcuts.Game(folder, exe)` = `Tsukihime.lnk` pointing
at Tsukihime.exe with the app folder as the working directory, the exe as the icon and the description "Tsukihime -A piece of blue glass moon- (PC port)";
`Shortcuts.Launcher` = `Tsukihime Launcher.lnk`. `ShortcutFolders` (desktop, Start menu > Programs > Tsukihime) is a property of the model, so the tests and the self-test write into
a temporary folder. The Play page's Quick settings card has a **Desktop shortcut** row (Create / Replace, the text says whether `Tsukihime.lnk` is on the desktop); the Game files page
has a **Shortcuts** card with "Desktop shortcut to the game", "Desktop shortcut to the launcher" and "Start menu entries" (both links). An existing file is replaced only after the
confirm overlay's "Replace"; a toast names what was created or the error (`COMException`, `IOException`, `UnauthorizedAccessException`). Renders read: `scratch/k20/launcher/render/play.png`
(the row under Button prompts with its Create button) and `gamefiles.png` (the card between the folder and the verification).

## 5. The dialog buttons in Japanese, and the audit of the port's own strings

**Finding.** The Yes / No buttons of every two-button dialog are DISP_PARTS child 19 of the UI language (knife `dialog_btn_ja`). The user's Japanese sheet is **byte-identical to the
English one** (`scratch/k20/dialog_btn_ja.png` = `dialog_btn_en.png`, `cmp` equal): the PS4's Japanese UI says Yes / No in English, as it says Save / Load / Config; the Chinese sheets
say 是 / 否 (zc = zt). `ui_text` has no はい / いいえ either (`samples/engine/ui_text_ja.tsv`). So there is no PS4 picture to use; the port draws the words.

**Change** (`UiDialogButtons`, used by `ConfirmDialog` and the story prompt `UiStoryPromptView`): in a language whose sheet speaks it (en, zc, zt) the cell is drawn as before; in
Japanese the word はい / いいえ (`PortText`) is drawn in the game's own Japanese glyph pages (`UiText.DrawGlowLabel`, scale 0.54, the line box from row 10 of the cell), white, or cyan
(0, 255, 240) with a faint glow under the cursor, over the sheet's own 1 px underline (rows 42.. of the cursor cell), where the sheet's letters sit (measured: rows 14..42, centred).
Renders read (`scratch/k20/ui3/dialogs_contact.png`): the overwrite question in ja (いいえ cyan with the underline, はい white), en (No / Yes), zc and zt (否 / 是), and the story's
save prompt in ja (いいえ / はい, the cursor on はい). Ink rows measured on the renders: ja 16..42 against en 15..42 and zc / zt 13..44. This is a PS4 vs port deviation on purpose,
for the whole game (one dialog in Japanese and the rest in English would be the odd thing); `UiDialogButtons.SheetIsLocalized` is the one switch.

**Audit of every string the port added**, in ja / en / zc / zt (`PortText`, `tests/.../PortTextTests` checks the four columns, the placeholders and that none shows "Tsuki" alone):
the first-run prompt and the dialog caption, the wrong-folder and gone / incomplete / unreadable folder sentences, "already running", the save-failure notice, the two damaged-save
notices, the FFmpeg, OpenGL and window start-up errors, the log-file notice, "Details:", the dialog buttons, and three entries for package K21 (screenshot saved / failed, text copied).
`GameApp` shows them through `PortText` with the start-up language (before the game data) or the profile's language (after). Already localized before K20 and left as they were:
the Display Mode / Window Size rows (K19), the Button Prompts row (K9), the story prompt's guide line (the game's own `help_txt` sheets per language). English by design: the title's
EXIT item (the PS4's five title items are English pictures in every language; `scratch/k20/ui3/ui_title_{ja,en,zc,zt}.png`), the key caps (Enter, Esc, ...), the device names
PlayStation / Xbox, and the whole launcher (an English program; its toasts included: not asked, section 8).

## 8. Open issues

1. The Japanese dialog buttons are the port's words in the game's glyph font, not PS4 art (there is none; section 5); the glyph face is the UI's serif-like Japanese face, the sheet's
   Latin letters are a sans. If the lead prefers the PS4's English Yes / No in Japanese after all, `UiDialogButtons.SheetIsLocalized` is the switch and `StoryPromptAppRealDataTests`
   and `DialogButtonsRealDataTests` need their Japanese expectations swapped.
2. The launcher stays English (every page, the toasts, the confirm overlay): localizing it was not asked; the game-side strings are the ones in `PortText`.
3. The game window's icon on Windows comes from the executable's own group through the window class; the embedded 64 px picture is the path for a host without the group and
   for other platforms. The taskbar button itself was not inspected (the capture of the taskbar did not include it); the class icons are set and the title bar shows the icon.
4. The first-run dialogs were seen only through their window titles and the exit code (the screen captures were occluded, section 7); a look by hand at the Japanese prompt text's
   wrapping in SDL's message box is still worth a minute.
5. The remembered game folder of a direct start moved into the profile folder; a user with `--save-dir` on the command line of a shortcut would be asked once more. The launcher's
   `--data` profile already kept it there.
6. `docs/status/knife/K6.md` .. `K19.md` and `R1-*.md` keep calling the program `Tsuki.App.exe` (their history); the README notes the rename under the verification command.
