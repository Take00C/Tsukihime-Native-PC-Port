# K7: the remaining visual effects (colour grades, stage passes, screen effects)

Owner: package K7. Specs: [`docs/formats/compositing.md`](../../formats/compositing.md) 7-9, [`layers.md`](../../formats/layers.md) 4, 9, [`system_flow.md`](../../formats/system_flow.md) 5.3,
[`docs/research/knife_tables.md`](../../research/knife_tables.md); knife (`grade.rs`, `stage.rs`, `game/focus.rs`, `game/ghost.rs`, `knife-render`) where the PS4 documents are silent.
Code: `src/Tsuki.Render` (Grade, Textures, Compositor, Shaders), `src/Tsuki.Engine/Stage` (draw side), `src/Tsuki.Engine/Game/Effects`, tests in `tests/*/Effects`.

Status: **done**, open issues at the end. Every effect K2 and K3 left undrawn now produces display-list commands, the renderer executes them, and each was rendered from a real scene
and looked at (PNGs in `scratch/K7`, described below).

### 1. STEC colour grades

`_STEC` / `_SNX2` / `_SNX3` go through one path: the stage hands the grade key to `TextureRef.D` (K2), the cache grades the decoded tile when it builds the texture, as the engine does at
texture build (compositing.md 9). SNX2 / SNX3 are the brightness and contrast LUTs of the same kernel call. The kernel was compared with the engine's own function under emulation:
**336 frozen cases, 0 differences** (`stec_golden.json`, ids 0..83 x brightness / contrast pairs including the clamping extremes). The PS4 LUTs are used, not knife's parameters.

### 2. Stage passes

* **Group pass (offscreen mask).** A layer that other layers name as `mask` clears target 1, draws its picture's silhouette (alpha times the layer alpha) into it (effect 58, blend state 4:
  alpha := source alpha), is drawn itself, and the layers it holds are drawn with `Fx.Mask = 1`: they are visible only inside the silhouette, and they fade with the window layer (a window at
  alpha 0.52 shows its character at 0.52; knife composites the group at the first layer's alpha as well). The crop window stays the scissor of K2. A window at alpha 0 leaves the held layers an empty mask.
* **STTR rule fade.** Target 1 is cleared and the rule picture (`RULE_nn` = allpac3 entry 85 + n, mirrored by the STTR flip bits) is drawn full screen into it with the **PS4 rule window**
  (compositing.md 7.4: a = 256 - trunc(256 progress), lo / hi from a / 128, width 1.0, inverted) for progress = 1 - layer alpha; the layer is then drawn through that mask at its own alpha
  (knife: the alpha is both the wipe progress and the colour). A layer that is both a rule fade and a window multiplies its silhouette into the mask afterwards (`MaskMultiply`).
* **STRA haze.** Each tile quad carries `QuadPass.Haze`: two waves along the picture's v axis displace the texture coordinates (x by a sine, y by a cosine); the amplitude, wave count and
  phases come from the PS4 haze table entry exactly as knife's `Haze::params` takes them from its (16 entries retuned for the PS4, read from the eboot), with the engine's phase counter
  (state machine 0x86EE0, modulo 6000). The wave coordinate is the picture-space v, so the tiles of one picture agree.
* **STNS noise.** A layer with `stns` 1..12 shows the NOISE_PARTS picture (two 1920 x 1080 opaque grey-grain pictures, mean 127.5; child 1 for `stns % 10 == 2`) instead of its own on the
  layer's rectangle: a whole-sheet quad (`UiTile`, tile -1) cut to 1 / 1.2 of the picture at a fresh pseudo-random offset every frame (every third frame for `stns` 1, 2), mirrored on alternate
  ticks (knife `noise_pass`). The layers that carry it are white `IMG2345` pictures, so the picture is only the shape. K2's `stns_b` counter still advances as before.
* **FADS types 18, 20..24, 68..70** (the engine-only screens). Decoded from the disassembly of the draw callback 0x67820 and checked by emulating it at five progress values (a helper
  agent's report, not kept as a file): 21..24 slide the old frame and the new scene by opposite distances, 20 cross-fades then redraws the frame line by line with a random offset over black,
  18 is a mosaic (shrink the new scene by N, capture, magnify nearest), 70 shrinks the old frame towards the centre while its scale circles, 69 whites the screen out and dissolves the new scene
  in through the rule picture during the last quarter, 68 draws nothing (its particle table is never filled). **None of them can run in the shipped game**: scripts use types 0, 1, 2 only, and the
  only other caller of the type store is a dead timeline player. Their geometry is the Vita 960 x 544 layout ported unchanged, so on the PS4 each draws a 960 x 544-texel crop at the top-left;
  `TransitionScreens` reproduces that exactly.

### 3. Game effects

* **FCLN focus lines** (effects 4..33): up to 400 strips of the FocusLine texture (EFFECT_PARTS child 3, 1920 x 128, 960 x 2 texels per line) rolled from the eboot keyframes, drawn with
  alpha blending under the message window (after the ghost, before a transition's capture, as knife's bucket order and the capture rule require).
* **Falling notes** (effects 1..3): simulated and drawn as sprites of EFFECT_PARTS children 0..2, which are **16 x 16 transparent dummies on the PS4** (archives_ui_movies.md 8): they move and
  show nothing.
* **FADE(40)**: the frame is copied (surface 8), each channel is drawn twice (unshifted, shifted) through its colour word into target 2, summed into target 3 (red replaces, green and blue add),
  and overlaid on the frame with effect 22 (ps_overlay) at the effect's alpha. FADE(41) fades it out. Because an overlay of a flat tone over itself changes nothing, the fringes show on mid
  tones and edges only.
* **Choice glow** (system_flow.md 5.3, VA 0xA6E10, PS4 numbers): the vignette (SELECT_PARTS child 5) over the scene and page text; for the cursor line and the previous line eight copies of
  the line's text in 0x77FF (0xC7FF once decided) at offsets of +-0.9 / 0.7 units, alpha `g / 8` with `g = h (or 1 - h) x a x 192 / 255`; the underline (child 2) that grows with the
  highlight and the flare (child 4) that pulses between 0.333 and 1, both with effect 0xB; after the decision the ring (child 3, turning and growing), the blue bands (child 0) and the lens
  flare (child 1). Sizes are the sheets' own (1455 x 48, 930 x 243, 982 x 985, 1920 x 1080, 1920 x 1920, 1929 x 1083), one texel per pixel.

## PS4 versus Switch (for knife_port.md 3)

| topic | PS4 | knife / Switch |
|---|---|---|
| STEC | evaluated LUTs on the CPU at texture build (0xD36F0), exact kernel above | shader parameters (`pre_alter`) |
| falling notes art | EFFECT_PARTS #0..2 are 16 x 16 transparent dummies: the notes are invisible | FallNote0..2 textures |
| focus lines | the FocusLine strip is EFFECT_PARTS #3 (1920 x 128); 118 of 120 keyframes equal knife's, the rest are read from the eboot | `LINES` literal |
| `rand()` | 30 bits (RAND_MAX 2^30 - 1); focus rolls share the stage's `Ps4Rand` | a private generator |
| rule window | width 1.0 in rule units (a = 256 - trunc(256 p), b = 256) for FADS and, here, STTR | edge width 128 / 255 of the range (`rule_soft`) |
| haze phase | modulo 6000 (the engine's state machine) | wraps at 31416 |
| FADS 18, 20..24, 68..70 | Vita-layout screens nothing starts | no such types |
| choice text | the doc lays lines out at 3.0 x 3.1332 px per unit (text_vertical_scale.md) | its own layout |

## Open issues

1. **Soft clip insets and rotated clip windows** (STCH a16 / a17, K2 open issue 3) are still not drawn: the window is the scissor rectangle. knife's `ClipRect::soft` needs the BORDER_PARTS
   alpha-gradation profiles; the mask target and `QuadFx` are the place to add it.
2. **The group pass is [H]** (layers.md 9 gives the order of the sprite calls, not the raster): held layers are masked by the window's silhouette times its alpha, one shared mask target,
   a held layer's own STTR is ignored, a held layer that is itself a window does not mask its own children (K2's draw order). The PS4 composite order of a window with a crop and a rule is not traced.
3. **Haze** (layers.md 4.3: draw not traced): knife's meaning of the ten table floats; the displacement is clamped at tile borders (up to about 7 px of smear at the seams of a 512-px tile);
   `GameHazeTable.TryGetEntry` copies the entry on every call (an allocation per layer per frame).
4. **Noise offsets** come from a frame-counter hash, not the engine's `rand()` (so they do not disturb the quake stream); `stns_b` is not used as the animation clock.
5. **Ghost / focus animation** is knife's (PS4 sub_2F910 / sub_86850 not traced); `FADE` kinds other than 40 / 41 are K3's. The focus line scale table and the keyframe mask 0x2930_3FFB are
   carried over from the Switch (layout data).
6. **Type 20 feedback**: the engine captures its own output into capture 0 every frame, so from the second frame the cross-fade weight compounds; it was emulated for one frame only. The nearest
   filter of the mosaic (filter tag 3) is [H].
7. **Whole-sheet quads (`UiTile`, tile -1)** are what K3 and K7 emit for UI sheets, noise, focus strips and the choice pieces: a texture provider must serve them
   (`GameTextureProvider.Assemble` does; K6's own uploader has to). `ChoiceGlow` reads the sheet sizes by decoding each SELECT_PARTS child once on the first choice (a header-only size
   API in `IGameData` would avoid about 100 ms; the call falls back to an empty decoration when the source has no SELECT_PARTS).
8. **K3 findings** (not changed here): the choice and page text are drawn at 3.0 px per unit vertically where text_vertical_scale.md gives 3.1339 (3.1332 for the choice canvas), and the English
   choice lines are laid out at width 474 where system_flow.md 5.3 gives 574 (line 3 wraps in `choice_004_1.png`). `ChoiceGlow` takes the pixel-per-unit factors as arguments (`GameHost.TextScale`),
   so correcting K3's constant moves the decoration with the text.
9. K2 issues 1 (grade rebuild policy), 5 (SHOK offset on the transition capture) and 6 (colour tween, rewind) are unchanged. `GradeKeys` is a process-wide table that only grows.
10. For K6: the restore of a running effect should call `host.Focus.Start(effect, 0)` and `host.Ghost.SetMode(4, p, q)` / `MarkWrapped()`; `StageRuntime.EffectPasses` can switch the passes off; set
    `TextureCache.Grader = TileGrader.FromEboot(reader)` wherever the app builds its cache (without it a graded key is uploaded ungraded).
