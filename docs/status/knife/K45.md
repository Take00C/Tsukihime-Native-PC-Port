# K45: deleting a save in game (issue #10)

Package K45, 2026-11-02, main tree on `d592a29` (v0.1.4), beside the flowchart fix for issue #9 (another agent, same tree; its files are not part of
this one). Nothing committed, no version bump. Builds in `artifacts/wf_del` (`-warnaserror`, 0 warnings). Game runs hidden and muted on temp profiles
in the session scratch folder; the game folder, `%APPDATA%\Tsuki` and the release folders were not touched.

## 1. Cause

`AppServices.Delete` refused every slot from 100 up (the auto saves), and `SaveLoadScreen` ignored its answer: it showed "Deleting..." and then
"Deleted." (217) whatever happened. The reporter's slots all carried AUTO SAVE, so nothing was deleted and the screen said it was.

## 2. What the PS4 does

Read from the eboot; the full notes are in `docs/formats/adv_state.md` 7.8.

| point | PS4 (VA) |
|---|---|
| which slots are listed | slots 0..99 only, in the Save list, the Load list and the title's LOAD GAME (builder 0x711F0; emulated by `tsuki.save_list_emu`). Auto saves and the quick save are never listed, so on the PS4 they can't be deleted at all |
| the delete key | TRIANGLE in either list (0x73107). It checks only that the slot under the cursor is used (0x7330F), never the slot number. Used: dialog 23, "Do you want to delete this data?". Blank: 193 "No save data found." and SE 1 |
| after Yes | "Deleting..." (188); the frame under the cursor fills in over 20 frames (0x72696, drawn at 0x70AEE). Then the slot's used word and date are zeroed and the file is written with the latest slot recomputed (0x726E3: SaveImage_Commit mode 2) |
| write finished | silent (SE 13 is an empty entry); 41 frames later the list is rebuilt, the slot's thumbnail is released (0x70E90), and "Deleted." shows for 480 frames (0x727B0) |
| write failed | 189 "Unable to save data." (0x7276A); "Deleted." is never shown |
| auto-save ring | there is no ring index. Each auto save moves records 100..137 down by one (0x73B70), and an empty slot simply moves down with them |

knife (the Switch build) lists 0..99 too; its delete waits 15 frames, plays SE 1 and shows "Deleted." for 300 frames. Those timings were ours until now.

## 3. Changes

- `SaveStore.Delete` returns false for an empty slot. It empties any stored slot and its thumbnail and recomputes the latest slot.
- `AppServices.Delete` accepts any listed slot (manual 0..99 and auto 100..138) and refuses the quick save and empty slots. It drops the cached
  thumbnail and returns false if the file could not be written.
- `SaveLoadScreen`: the delete runs as the PS4 does (section 2) and uses `Services.Delete`'s answer: "Deleted." only after a real delete,
  189 otherwise. A blank slot plays SE 1. A failed Copy now rebuilds the list too, since the copy may still be in memory.
- `MessagePopup.StepBackground`: a released popup now fades out under the one that replaced it. Before, "Deleting..." stayed under "Deleted."
  and showed again after it closed.
- `IGameServices.Delete` doc, `PreviewServices.Delete` (refuses empty slots and the quick save; `DeleteFails` for tests).
- Docs: `adv_state.md` 7.8 (new), `engine.md` 7.4 (the list is 0..99). Tool: `tools/tsuki/save_list_emu.py`.

## 5. Open items

1. **The auto saves in our Load list are a port addition** (K5a marked it as a guess). The PS4 never lists them. They stay listed, and now they
   can be deleted. Matching the PS4 exactly would mean removing them from the list, so players could reach them only through Continue. The user
   chose to keep them deletable (section 6).
2. The PS4 has no Copy Data: SQUARE does nothing in the list (0x730F4). Ours copies, as knife does. Left as is.
3. The PS4's save makes no sound when it finishes (SE 13 at 0x72DEC); ours plays SE 1 (from knife). Not changed here.
4. The PS4 keeps a deleted slot's record bytes and zeroes only the used word and date. Ours drops the record. No reader looks past the used word,
   so this changes nothing a player can see.
5. Launcher, not edited: after a Restore, the message always says "The previous save is in the backup list.", even when there was no save to back up.
