# K47: Steam Deck and macOS support

Package K47, 2026-11-03, on Kimi's branch `kimi/macos-steamdeck`, with four review rounds. It reached the owner's repository together with K48 in `f87fdd2`; the branch's own commits are not in this history. The version remains **0.1.6**. No game data or artwork was added, nothing was pushed, and no local release archive was created.

## 1. Steam Deck

- The default is Linux-only: explicit `--windowed`/`--fullscreen`, then an explicit `display_mode=` choice, otherwise fullscreen on every start, including consecutive starts after `save.dat` is written. F11 and Config > Display Mode record that choice on Linux even when the config byte already has the same value. The default itself writes nothing and logs `window: Steam Deck default fullscreen` and `window mode: fullscreen (Steam Deck default)`. A `--windowed`/`--fullscreen` flag on the Deck holds for that start only.
- A two-start regression test calls the same loaded-settings helper as GameApp with a real settings path and config block. Separate tests prove that a same-byte Windowed choice is saved on Linux and that Windows gets no new key.
- `docs/LINUX.md` documents the default, Launch Options, Steam Input and the shared Linux profile. The 16:9 picture is letterboxed at 1280 × 800. There is no separate Deck package or updater asset.
- The earlier audio-device reopen path was removed because it repeatedly disposed SDL's only audio reference. Startup and silent-failure behavior is again the v0.1.6 code; physical hot-plug and sleep recovery remain hardware checks.

SteamOS still needs the system libraries already established by dependency inspection: the apphost needs `libdl.so.2`, `libpthread.so.0`, `libstdc++.so.6`, `libm.so.6`, `libgcc_s.so.1` and `libc.so.6`; SDL needs `libm.so.6` and `libc.so.6`. Round-5 inspection of the real Linux publish also found that Skia needs `libfontconfig.so.1` and `libfreetype.so.6` (with Expat, zlib, bzip2, PNG and Brotli dependencies). These are documented in `docs/LINUX.md`. Linux FFmpeg `ldd` evidence remains outstanding because this WSL installation has no FFmpeg 9 libraries and the structural publish deliberately leaves them out.

## 2. macOS runtime and profile

- Added `osx-arm64` and `osx-x64` native names for SDL and FFmpeg, plus the forward-compatible OpenGL context flag. The app requires **macOS 15 or newer** and is marked **experimental / untested on real Mac hardware** in the player guides.
- Retina rendering uses drawable pixel sizes for the viewport and render targets, not window points. Game path handling does not assume every drive is case-insensitive; case-sensitive external drives remain supported. Root-scan refusal on macOS is limited to `/`.
- The default profile is `~/Library/Application Support/Tsuki`; screenshots go to `~/Pictures/Tsukihime`. `--save-dir` selects an explicit profile. The Mac profile test calls the real platform API on macOS rather than injecting an expected value.
- macOS launch ignores `-psn_*`; trackpad scrolling uses integer ticks; green-button/system fullscreen is remembered like F11 (macOS only; Windows and Linux keep v0.1.6's handling); `NSSupportsAutomaticGraphicsSwitching` is enabled.
- macOS module checks enumerate dyld images rather than relying on `Process.Modules`. Full smoke reports GLSL ES 3.00 as informational: Apple's OpenGL 4.1 core profile has no GLSL ES 3.00, and the game uses GLSL 3.30 core. Headless smoke checks FFmpeg/audio without a GL window.

## 3. FFmpeg and app packaging

- `tools/setup/ffmpeg_macos.sh` builds on the matching Mac architecture from official FFmpeg source. Default `n9.0.2` is pinned to `946fcce07b6dcd0331c8cc609192aeff5e1924f8` and fails on a mismatch. A new checkout uses a depth-1 fetch; an existing checkout must have the official origin; every build compiles a fresh `git archive` extraction, not a reused worktree.
- The build is shared, minimal and **LGPL 2.1 or later only**, with macOS 15 as the minimum and no GPL, nonfree, version-3, external codec or network components. Intel builds require `nasm`; pthreads are explicit.
- Configuration uses neutral `/usr/local`; `DESTDIR` stages the install. `FFmpeg-SOURCE.txt` records the exact commit and a `./configure` command, rejects builder home paths, and labels its hashes **before ad-hoc signing**.
- A publish without the required macOS FFmpeg files stops with **TSUKI003**. The `TsukiBundleFFmpeg=false` system-library option is Linux-only; macOS always bundles its dylibs and has its own missing-library message.
- `tools/setup/package_macos.py` assembles `Tsukihime.app`, generates the ICNS only from existing crescent PNGs, and ad-hoc signs on macOS by default. `--no-sign` is structural-check mode; `--zip` uses `ditto` on macOS only. Successful packaging removes its temporary parent folder.

## 4. Release validation, documents and CI

| point | decision |
|---|---|
| app and ZIP checks | Parse bounded Mach-O load commands for exact dylib IDs/dependencies, minimum OS, signature and platform. Apphosts and required native libraries require platform 1 and a minimum no newer than macOS 15. `LC_VERSION_MIN_MACOSX` reads deployment (+8), not SDK (+12). Universal launcher libraries are validated per selected architecture; apphosts stay thin. Plist notes are emitted only when no problem was found. |
| bundle signature | A release ZIP needs `Contents/_CodeSignature/CodeResources`. The main launcher uses `io.github.take00c.tsukihime`; the nested game host uses `io.github.take00c.tsukihime.Tsukihime`, which `codesign --deep --prefix io.github.take00c.tsukihime.` gives it. An SDK-signed bare apphost is not a signed bundle. Unsigned structural folder checks remain available. |
| paths and entries | Loader-relative dependencies must name an existing direct child of `Contents/MacOS`. ZIP validation refuses unsafe/control names, `__MACOSX`/`._` metadata other than ditto's signature entries, case-insensitive duplicates, links/special files, setuid/setgid/sticky bits, files over 512 MiB and uncompressed apps over 2 GiB. |
| updater isolation | One test builds a Windows ZIP, Linux tar.gz and both Mac ZIPs into one `SHA256SUMS.txt`; the Windows updater matches only its own line. It skips explicitly when the Windows apphost is unavailable. The Mac ICNS exemption applies only to Mac bundles. |
| publish documents | Every archive carries both platform guides. Link checks model per-platform resource maps and pin them and the ICNS construction to the packaging script. `RequiredDlls` is pinned against literal native-library lists. |
| push CI | `macos-15` builds ARM64 and `macos-15-intel` builds x64. `setup-dotnet` and `cache` v6.1.0 are pinned by full SHA and use Node 24. Intel installs `nasm` only on a cache miss. Unsupported EGL/offscreen Mac smoke is not attempted. |
| manual download CI | Separate `macos-release.yml` runs only on `workflow_dispatch`, always builds pinned pristine FFmpeg, signs and zips each app, runs `release-check`, `release-sums` and headless smoke, then uploads with `upload-artifact` v7.0.2 and `archive: false`. Summaries record the source commit, `nasm`, clang, Xcode and ZIP SHA-256. It never pushes or creates a GitHub release. |

`PUBLISHING.md` gives the four maintainer steps: run the workflow on `main`, download both artifacts within three days, run `release-sums` once with every asset, and attach all four archives plus `SHA256SUMS.txt`. `MACOS.md` says **Option+Return** for fullscreen and **Fn+F12** for screenshots, and says to use **Open Anyway** again after replacing the app if macOS asks.

## 6. Not verified here

2. Ad-hoc signing with Apple tools, `ditto` ZIP creation, bundle identifier/CodeResources validation on a real signed app, Gatekeeper behavior and launching a downloaded app.
3. Real macOS OpenGL rendering, dyld image reporting, audio-device changes, trackpad/system fullscreen, sleep/resume and gameplay on Apple silicon and Intel.
4. SteamOS Game Mode, physical Steam Deck sleep/resume, repeated starts and remembered window choices, audio-device transitions, and end-to-end Steam Input behavior.
5. Physical Windows/Linux audio hot-plug and sleep recovery after removing the reopen path.
6. Hosted push CI or the manual Mac download workflow; local commands above do not prove the hosted runners or uploaded artifacts.
7. Linux FFmpeg `ldd` inspection.
