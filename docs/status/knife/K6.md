# K6: the playable app (composition, services, restore glue, input, verification mode)

Package K6 of the knife-reference wave. Run on 2026-10-26. Every number below comes from a command run in this session.
Nothing is committed (the lead commits after review). All runs used a **hidden** SDL window (`SDL_WINDOW_HIDDEN`, never focused) and **no audio device**
(`--mute`: the mixer is pulled by the loop and the samples are dropped; `--hidden` implies it); the user's `%APPDATA%\Tsuki` was never touched
(every run used `--save-dir scratch\K6\...`, the tests no save path or a temp folder).

## 1. Result

`Tsuki.App` is the game: it boots through the autosave notice and the title, plays the prologue and the story with text, characters, choices,
movies and sound through the mixer, and has working menus, saves, quick save / load, rewind, backlog, gallery, flowchart, config with live
language switch, and a verification mode for agents.

## 3. The restore glue (K3 open issue 1, K4 open issue 1)

`AdvHistorySink`, `AdvHistory`, `SaveStore` were already there; `GameHost.Restore.cs` applies what they return (`ApplyRestore`):

1. the runtime resets like a scene start (waits, choice, page, movie state, effects; the auto bit and the replay flag are kept, the skip latch is cleared);
   every audio stream is stopped and the full-screen movie closed (commands go out through `TakeAudioCommands` / `TakeMovieCommands`);
2. **stage**: a fresh `StageRuntime`; kinds 1 / 9 (`RebuildFromCommitted`) commit `live.Committed` first and then `live.Scene`, every other kind commits `live.Scene`;
   two `Update`s move B to A and end the zero-length transition before the first draw (no flash of the previous frame);
3. **sound**: `SoundModel.RestoreScriptState` starts the BGM (`BgmTrack`, `BgmVolume`; track 0 at volume 0 is the fresh model's "none") and every loop SE whose id >= 0 and
   loop flag > 0 (volume, pan, character) on the fresh model; the play commands are drained at once. A load / previous scene replays the record's voice through the
   usual voice gate (`SetPendingVoice`, VA 0x7EB19);
4. **script**: `ScriptVm.Seek(script, offset)`, `MarkerState.Restore`; a load / previous scene / backlog jump runs the saved statement again (`_ZM` pushes a new record and shows the
   line), a **rewind re-displays** the line from `RedisplayInfo` (text expanded and laid out as `_ZM` does, end code -> click / continue / no-wait wait bits, window open) and the script
   resumes after its statement; the message window opens for kind 0 / 12 / 13 records;
5. `Restored` event / `LastRestore` report (kind, script, offset, record kind, redisplayed, BGM track, loop SEs).

Not filled (still zero in a record, no visible effect): name-plate bytes (`Window164FD00/40/60`), speaker, the deferred-SE channel table, `SeArrD`, effect-slot bits other than the movie (K3 issue 2).

Language: the interpreter's language is fixed per `GameHost` (K3 issue 12), so a language change builds a **new host over the same profile** and, in a story, loads the current page into it through a
temporary `SaveStore` slot (page-start granularity; the Japanese page and the English page both verified in the real app, section 5).

## 4. The verification mode

```
Tsuki.App --hidden --mute --autoplay skip --fast --save-dir <dir> --shot-dir <dir> --shot-on-choice          # boot to the first choice, writes first_choice.png
Tsuki.App --hidden --mute --autoplay click --fast --save-dir <dir> --shot-dir <dir> --script "1500:autopause;1510:Esc;1580:shot=menu;1590:Decide*2;1660:shot=save_list;1700:log" --exit-after 1710
```

* `--hidden`: hidden window, implies `--mute`; `--fast`: unpaced steps (one render per step) and virtual movies; `--movies real|virtual`; `--autoplay` modes: `click` (Enter every other frame), `skip` (plus Ctrl held),
  `auto`; the title and boot are clicked through; choices by `--choices first|last|random[:seed]|list:i,j`; `--shot-on-choice` holds the first choice open, writes `first_choice.png` and stops (unless `--exit-after`).
* Script (`--script "frame:action[+action];..."` or `@file`; frames are logic steps, 60 per second): `Key` / `Key*N` (held N steps), `click=x,y` / `rclick` / `move` (canvas pixels), `wheel=n`, `shot=name`,
  `log` (prints script, scene, offset, F823, auto / skip, history count, restore count, the line), `lang=ja|en|zc|zt`, `autopause` / `autoresume`, `quit`. `--shot-at f,...` writes `frame_NNNNNN.png`.
* The run ends with a summary: steps, wall time, textures resident, tiles decoded, frames that waited for textures, movie frames, mixer peak, audio / movie failures, restores, unknown commands, and timing
  (step / draw means and maxima). `TSUKI_DUMP_FRAME=n` prints the display list of step n.
* Without a script or autoplay the same code reads the keyboard, mouse and pad (`PcInput`), also in a hidden window.

## 7. Open issues

1. **Never run with a visible window or an audio device** (the rule of this session). Verified: the hidden-window loop with `PcInput` and `Present`, the pure input mapper and letterbox (unit tests), SDL polling code compiles but real key / mouse / pad events
   were not exercised; `AudioOutput.OpenDevice` is the H1 / K1c path, not opened here. First thing to do on a desktop: play ten minutes with keyboard and mouse, then a pad.
2. **Stage draw gaps** (K2 issue 3, K7's area): window / masked layers are drawn as a scissor rectangle (scene 240's ceiling CG shows as a 888 px band with white beside it); no blur pass behind the system menu; the STRA haze and some `_FADS` screens.
3. **Choice screen** (K3 issue 6): the previous page's text stays visible and overlaps the choice lines; no cursor glow, underline, flare. The mouse hover / click works.
4. K3 issue 8: no name plate, click icon or second window (so the speaker's name is not shown outside the text); `Window164FD*`, speaker and channel-table bytes of a record stay zero.
5. A save, quick save or load restores the **start of the logical page group** (messages joined with `@n` count as one record): that is the engine's `Staging_SetSnapshot` rule (K4, verified against the engine), so the slot's notes show the first line of the group.
   A backlog jump to a mid-page entry rebuilds only that line (the page's earlier lines are not re-shown).
6. Hitches: opening the first looping movie (title) blocks the main thread for about 240 ms; a script switch costs 45-70 ms (decode on the main thread); `TextureFeeder` waits up to 300 ms for tiles of a new scene (no prefetch).
   The texture cache cap is 1.5 GB: a skip run through several CG scenes reaches it.
7. Window mode is kept in config byte 0xA9 (an unused area); "Recommended Settings" resets it to windowed. The window size is not remembered. `--hidden` and `--fast` are verification options only.
8. The pad's `DecideIsCross` is fixed to true; there is no key-rebinding screen (the PS4's action presets are not exposed).
9. `SeekTitleMovie` is a no-op (the movie pipeline wraps at 8.0333 s by itself); the movie pause / hold under a submenu (K1c issue 7) is not implemented; the voice test in the config screen plays the last voice heard in this run only.
10. Fonts and sheets of a language that is not selected are decoded on demand (first use of a language costs a short wait).
