# K35: review of K34 (the click-wait marks), re-derived from the eboot and checked in hidden runs

Package K35 (label `k35`), the independent review of K34 (docs/status/knife/K34.md), run on 2026-10-31 on top of commit cbf260c with K34's
uncommitted tree. Nothing is committed. Builds in `artifacts/k35` (`-warnaserror`, Debug and Release, 0 warnings). Every game run hidden and
muted (`--hidden --mute --fast`, `SDL_AUDIO_DRIVER=dummy`, BelowNormal priority) on its own `--save-dir` under `scratch/k35/` with `--no-save`;
the game folder, `%APPDATA%\Tsuki`, `%APPDATA%\shadPS4`, `artifacts/play*`, `artifacts/dist`, `D:/TsukihimePort-public` and
`D:/TsukihimePort-release` were not touched. No PowerShell with Add-Type, DllImport, P/Invoke, LoadLibrary, base64 or Invoke-Expression (the
runs were started from bash; one `pwsh` line lowered the process priority); the crops were made with Pillow from `.venv`.

## 1. Verdict

K34 is right. The three marks, the alpha ramp, the anchor, the stored position, the selection and the animation match the PS4 code as I read
it myself from the disassembly (section 2) and as the emulator reports it for two scenarios K34 did not have (Simplified Chinese line mark,
Japanese bubble; section 3). The icon shows in ja / en / zc / zt at a line wait and at a page end, and is absent in auto mode, during a
fast-forward, with the window hidden and under the system menu (section 4, every crop read). The choices' first line still sits at the
click-icon y plus two pitches (K8's 191.04 / 179.04). One small defect fixed (section 5): the engine's "what the last frame drew" report kept
the last mark while the window was at 0 or hidden, so the verification log showed a mark that was not on screen.

## 2. Rules re-derived from the eboot (disassembly, independent of K34's notes)

Read: `scratch/textbox/hud_53cf0.asm` (lines 100..160 and 600..1010), `scratch/k34/f_53630.asm`, `scratch/k34/f_ca690.asm`.

1. **Alpha** (HUD VA 0x53F68..0x54014). `fade = [0xDF0730]; if fade <= 0: skip. r = 0xCA690(slot [0x16541D4] + 4, 0x30, &x, &y, head [0x1653E80],
   tail [0x1653E84]); if r == 0 or (E00 [0x1653E00] & 0x400) == 0: [0xDF08E4] = 0; else a = [0xDF08E4] + 0.1 (0x1A70DC); [0xDF08E4] = a; if a > 1: 1`.
   Matches `GameHost.UpdateClickIcon`. Edge: 0xCA690 returns -1 (nonzero, "complete") for an unregistered block slot; the port's
   `Block.Empty` check gives alpha 0 there instead; no script reaches it.
2. **Anchor, VA 0xCA690** (`f_ca690.asm`). Line origins: `ys[i] = sum(leading + lh[k], k < i)` (0xCA720..0xCA73E), `xs[i] = 88` (0x42B00000 at
   0xCA910) or the centre / right rules with flags `esi | block+8` (0x100 / 0x200), the vertical rules with 0x400 / 0x800; the record loop
   (0xCABCD..): `[rec+0] == 0` skipped; `ctr > head` -> alpha 0 and skipped; alpha = 1 when `tail > ctr` (0xCABE9) or `0 >= head - tail` (0xCABF3), else
   `(head - ctr) / (head - tail)` (0xCAC01); `flags & 2` (ruby) skips the position; `flags & 0x10000` -> `x = MirrorX[0x3ED90() == 1] - dx - w' * sx +
   xs[line] - 16` with `w' = w - 5` only when `w == 0x43 and tex == 0x5E` (0xCAC41..0xCAC56); else `x = (x2 - x0) * sx + dx + xs[line] + 3`;
   `y = dy + ys[line]`; `vcvttss2si` both; result `alpha == 1.0`. Matches `MessageWindow.ClickIconAnchor` line for line (including the
   `0x43 / 0x5E` quirk and `BlockDraw.LineOffsets(block, 88, 0, 0x30)` OR-ing the block flags).
3. **Stored position** (0x549C7..0x54B80). F822 != 1 -> origin (169.333, 43.1407), jump to 0x54BD8, x unchanged. Else `w = F1105 (F1109 in English
   when > 0); if F1111 >= 3: w = F1111; subtract = 87 (0x1A715C) if w >= 3 else the origin x before the F1106 shift; x = trunc(float(x) + origin_x'
   - subtract)` where origin_x' is the origin after the F1106 / F1107 (F1112 / F1113 with F1111 >= 3) table shifts; `[0xDF088C] = float(x)`,
   `[0xDF0890] = float(y) + origin_y` (0x54CB1..0x54CD7). Matches `DrawClickIcon` (`subtract = window >= 3 || F(1111) >= 3 ? 87 : 30 / 87`, the
   port's page origin has no F1106 shift, K15's rule).
4. **Selection and offsets** (0x54CDF..0x54F94, 0x53630). `if [0xDF08E4] <= 0: none. valid = x >= 0 || y > 0. w = F1105 / F1109 (English). w > 2:
   if !valid or auto bit [0x17DB230] & 1: none; a = alpha x fade; y + origin_y + 2 (0x1A7168), x - 2 (0x1A716C); tick = max(0, delta) + [0x78122C] mod
   118 (byte row = tick / 2), table 0x781230; colour(a, 1, 1, 1); scale 0.333; TexDrawRect(slot 4, 0x10, 0, &row, x, y)`. `w <= 2, F822 != 1: if auto:
   none; y + 2, x + 115 (0x1A7174); mod 210; a x 0.5 (0x1A70D4); table 0x781410, slot 3`. `w <= 2, F822 == 1: x = (-57 if English else 0) + x - 3.7;
   y = y + origin_y + 4.3; 0x53630(F799, x, y, alpha x fade)`; inside: auto -> return; `kind == 2` -> slot 4 / table 0x781230 / mod 118 / factor 1;
   `kind == 1` -> slot 3 / 0x781410 / factor 0.5; else slot 2 / 0x781760 / factor 1; mod 210; row = tick / 2 (signed int16 halving). Matches
   `DrawClickIcon` and `ClickIconCells`. **Note** (not a bug in play): `0x53630` draws the *bubble* table for `F799 == 2`; the port draws the line mark
   for every `F799 != 1`. The script dumps hold only `_WNTY(0)` (703) and `_WNTY(1)` (15,759), so the two agree on every script.
5. **Bubble path modulo**: `imul 0x22B63CBF; sar 0x24` is the signed division by 118, and the row is the signed byte `(tick + sign) >> 1`; the 210
   path uses `imul -0x63F63F63; shr 0x20; add; sar 7` and the int16 halving. Both are `tick / 2` for the non-negative ticks the counter holds
   after the first frame (the -1 start plus delta 1 gives 0).

## 7. Open issues (K34's remain; nothing new blocks it)

1. K34's open issues 1..5 stand (F822 != 1 origin, the mode banners, the second window F1111..F1113, the alpha carry-over in a fast-forward, no PS4
   capture). The second window: the PS4 also moves the origin to window F1111 and shifts the message by F847 blank lines (0x54A0A, 0x54B85..0x54BD3);
   the port's `WindowIndex()` ignores F1111, so when that window is ever drawn the mark's x shift (-57 for an English page) will need the same origin.
2. `0x53630` picks the bubble table for `F799 == 2` (section 2 item 4): no script does this; the port would draw the line mark.
3. The `icon` field of the verification log describes what the engine drew; under the system menu the app drops the page draws, so the field
   can say a mark while the menu hides it (seen at 2600 in the line runs). The screenshot is the evidence there.
4. The full Data run had one failure, K23's WebSocket app test (section 6), which passed alone: a load-timing flake of that test, not of K34;
   a lead rerun of the suite on a quiet machine is the clean proof.
5. K34's section 4 (no auto / skip banner on the PS4) was spot-checked only: `eboot.disasm xref 0x562D0` lists the five callers K34 names, and the
   call sites at 0x61BB2 / 0x6F250 pass `edi = 0`, 0x6D57F / 0x6D8C0 pass `edi = 1` (0x6D4DC not re-read). The banner function itself was not re-derived.
