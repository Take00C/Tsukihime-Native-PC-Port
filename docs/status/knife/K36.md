# K36: the per-character voice rows of Config > Sound (issue: "no character volume sliders")

Package K36 (label `k36`), run on 2026-11-01 on top of commit 59380ca (v0.1.1). Nothing is committed. Builds in `artifacts/k36` (`-warnaserror`,
0 warnings). Every game run hidden and muted (`--hidden --mute --fast`, `SDL_AUDIO_DRIVER=dummy`) on its own `--save-dir` under `scratch/k36/`;
the game folder, `%APPDATA%\Tsuki`, `%APPDATA%\shadPS4`, `artifacts/play*`, `artifacts/dist`, `D:/TsukihimePort-public` and
`D:/TsukihimePort-release` were not touched. No PowerShell with Add-Type, DllImport, P/Invoke, LoadLibrary, base64 or Invoke-Expression; the
one scratch script is Python from `.venv` (`scratch/k36/make_old_save.py`, run with `-I`).

## 1. The report and the cause

A player (Config > Sound in English, mid-story at "1/Homecoming I") saw Music, SFX, System Effects, Mute in Background, Play All Voices and
Interrupt Voices on Advancing Text, and no character rows, so every character stayed at the default voice volume (50 %, not 40 %: 40 % is the
music and SFX default; the row defaults are config +0x76 + 2k = 50, VA 0x3EAC0).

The PS4 shows one row per character **once that character has spoken**: the `_VPLY` / `_VPL2` handler writes three marks into the persistent
G words (section 2), and the config screen builds the row list from them when it opens. The port's config screen (`ConfigScreen.BuildVoiceRows`,
K5a) read those words correctly, but **the port's engine never wrote them**: the sound model's `_VPLY` only stored the pending voice and the
character; no code set the heard bit, the slot's last voice or the row bit. So every profile had every row word at 0 and the list was always empty.
The test buttons were fed from a run-time dictionary (`_lastVoiceOfSlot`) instead of the PS4's G[31 + k], so they could not have worked after a
load either.

## 2. The PS4 rules, read from the eboot (text VAs of CUSA47999 01.01)

Disassembled with `tools/eboot/disasm.py` (`func`, `dis`, `xref`); cross-checked with knife `ui.rs` `refresh_voice_rows` / `game.rs`
`note_voice` (Switch): the two agree on every rule below, with the Switch's 0x3CF36 being the complement of the PS4's 0x430C9 within 19 bits.

1. **The marks** (sound_runtime.md 3.6; adv_state.md 9.4). `_VPLY` / `_VPL2` handler at 0x968B2: `cmp byte [0x174DE48], 0; jne` returns at once in
   scan mode. 0x99EF7..0x99F08: the group table lookup on the name's first three bytes gives the character (word 0x1654208), then
   `or word ptr [0x164C6B2], dx` with `edx = 1 << cl`: **G[73] |= (u16)(1 << character)** (characters 16..23 shift out of the word). 0x9A022..0x9A058:
   the entry (the previous pending one for a name starting with `_`, else the hex argument into 0x16541FC / 0x1654200 / 0x1654204), then
   `call 0x3D260(character, entry)`. **0x3D260**: returns for character 0x17 (23) or a negative entry; `k = (int)log2f(mask[character < 24 ?
   character : 0])` (mask table 0x86A850); `G[0x1F + k] = (u16)entry` (`mov word ptr [0x164C620 + rax*2 + 0x3E], bx`); `G[words[k]] |= 4`
   (`or byte ptr [0x164C620 + rax*2], 4` with `words` = i32[19] at text VA 0x1A6850, the table `IUiTables.VoiceRowWords` already read by K1b).
   All 19 row words, G[31..49] and G[73] lie in G[0..499], the part of the G words the system block persists (adv_state.md 7.5).
2. **The row list** (0x3DF20, the only reader of 0x1A6850 besides 0x3D260 and the test button; called from Config_ToMenu 0x3E4A0 at 0x3E69B when the
   config opens). For rows 0..18: the row's items 96 + 5r .. 100 + 5r must lie in the page's item range ([0x66F260], [0x66F264]); `al = G[words[r]]`;
   `test al, 4; jne` else the row is disabled (its layout zeroed, face / name -1, 0x3E08C..0x3E0C7). A shown row gets its volume item from cfg
   +0x76 + 2r and its mute item from `(cfg+0x3C >> r) & 1 == 0` (0x3E0E8..0x3E120), its y from the count of shown rows (0x3E125..0x3E1AC, the
   370.01 + 50.607 n of K5a). Face: rows 15 / 16 (`lea eax, [rbx - 0xF]; cmp eax, 1`) show face 18 unless `G[words[r]] & 1` (0x3E1C9); name: rows
   whose bit of 0x430C9 is clear show name 19 unless `G[words[r]] & 2` (0x3E223..0x3E23E). Row 0 (Shiki): in a story ([0xE20CC8] != 0, the ADV
   mode word) hidden while F023 == 0 (0x3E29C), face 19 / name 0 when the script word [0x86AA18] == 1, face 18 / name 19 when it is 2 or 3, else
   0 / 0 (0x3E2A7..0x3E321, 0x3E3B2..0x3E46D); from the title, face 18 / name 19 until node 485 is reached (0xB81A0(0x1E5)), then face 19 / name
   0 until node 1 is (0x3E326..0x3E3DA). **0x3DF20 never reads config +0x16**: Play All Voices does not hide or dim the rows. There is no voice
   master slider on the PS4 Sound tab (page 1's rows 3..6 are the two radio pairs; adv_state.md 9.3).
3. **The test button** (item 99 + 5r -> 0x401E0, from the item handler 0x3FB10 at 0x3FF9D): nothing while `G[words[r]] == 0` or
   `(i16)G[31 + r] <= 0`; else `[0x66C720] = r` and `VoiceRequest(G[31 + r], -1)` (0xC3A80). Every config item ends with Config_FromMenu (0x3E6E0)
   and **Sound_ApplyConfig(0)** (0x4008C..0x40093). Sound_ApplyConfig (0x3E9B0) with full = 0 and a test row >= 0 (0x3EA25..0x3EA89): the row's enable
   bit clear -> 0x8EA0 (stop the voice); then `cfg.76[row] * cfg.16 / 100` -> 0xB6F0, which writes volume byte 0xD and sets the playing voice
   stream's volume to `clamp(trunc(gain * record volume * 0.01), 0, 100) %` (0xB6F0..0xB765). So the test plays at the row's volume, and while it
   plays the row's slider and mute act on it live; 0x3F870 (the config's open) resets 0x66C720 to -1. A scene voice takes its gain once, at its
   start (the gate of 0x9281E, sound_runtime.md 7 step 2: `char_vol[k] * cfg.16 / 100`).
4. **Volumes in the mixer**: unchanged from sound_runtime.md 2.4 / 7: the voice stream plays at `vol_byte[0xD] * 0.01` with the byte set by the gate
   per voice; the music / SFX / system bytes are separate. Play All Voices is the master (100 / 0) multiplied into every character's gain.

## 4. Existing players

Every save of v0.1.0 / v0.1.1 was written without the marks. The PS4 keeps nothing else that says who spoke, but the read-text table does:
`readmax[block]` holds the highest line of each text block whose marker was passed (the Z handler records a marker's line when the next one is
reached, adv_state.md 6). A `_VPLY` always precedes its `_ZM`, so **a voice statement whose next marker counts as read ran on the PS4 too**.
`VoiceMarks.RebuildFromReadText` walks the 549 scripts once, credits every `_VPLY` / `_VPL2` before a read marker with the handler's marks (heard
bit, row bit, G[31 + k] = the last entry in script order; a `_name` after a `_ZM` or a `_VPL2` finds no entry, as on the PS4), and runs at start when
`G[73] == 0` while `readmax` has an entry (the first voiced line of the game, 00_00, sets G[73], so a profile that played anything with the marks
in place never qualifies again). The marks are captured into the system block and committed at once.

What the player sees: nothing changes on screen at start; the next Config > Sound shows the rows of every character heard in the text they have
read, with the default 50 % sliders, and the test buttons play. The only deviation from a PS4 that had kept the marks: the test button of a row
plays that character's last voice *in script order of the lines read*, not the last one heard in play order; the next line of that character
corrects it. A line read on a path the player did not take is impossible (readmax only records passed markers), and the current line's voice is
credited by its own replay or the character's next line. Measured on a real profile (section 6): 162 statements credited in 474 ms at start, the
row set identical to the one the marks had produced.

## 7. Open points

1. Not verified against a running PS4 (no shadPS4): the rules are read from the disassembly and agree with knife's Switch reading; the hidden runs
   verify the port against those rules.
2. A profile that read text but whose only voiced lines were `_name` statements after their messages (entry -1) would be rebuilt every start
   (`G[73]` stays 0 only when no character at all is credited); the walk costs about half a second and the first voiced line ends it. Not seen in
   the data: 00_00 (script 1) has 140 voice statements.
3. The port forgets the test row when the config closes; the PS4 when it opens. No observable difference (the test row only matters inside the
   config).
4. `Sound_ApplyConfig(1)` (the full form) is what the port calls on every config change, so volume byte 0xD is reset to config +0x16 between
   voices more often than on the PS4 (which calls the full form at load and on close). Invisible: every voice sets the byte at its start.
