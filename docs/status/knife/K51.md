# K51: hard stepped edges on lighting overlays inside cut-in windows (issue #14)

Package K51, 2026-11-22, version **0.1.10** (branch `v0.1.10`, not released; the build still names itself 0.1.9). Fix 78d4e8f. No game data or story
text was added.

## 1. The report

Issue #14 (v0.1.9, fullscreen and windowed, every resolution): the light overlay of some scenes looks pixelated instead of soft. The reporter's picture is
`00_00` (scene 240), message 320 (step 10926 in a `--fast` run from `30:scene=240`): over the two cut-in windows a blue and violet field ends in a hard
staircase of steps about 10 x 5 px, with a dark red band under it and a straight tile edge near y 730.

## 2. Cause

Some lighting pictures keep full colour under texels whose alpha is only 0..2, and the edge of that hidden colour is stepped in the file: IMG2230 stays
(28, 139, 220) out to alpha 2, then drops to (0, 0, 0, 0); 366,948 of its texels have alpha <= 2 and a colour. In a cut-in window (a layer held by a
window layer, layers.md 9) the scripts draw such glows in blend modes whose colour ignores the picture alpha (here `_STBR 1`, add), so the port drew the
whole hidden disc. Sampling is not involved: linear samplers, no mipmaps, no magnification.

## 3. Fix

- `QuadFx.Held`: `StageDraw` sets it on the quads of a layer a window holds (plain, haze and noise paths). Windows, silhouettes, rule and soft masks,
  layers no window holds and `EffectPasses = false` never set it.
- Compositor shader: for held quads in modes 1, 4, 6, 8, 10, and 5, 7, 9 without the `_STBR` flag, `rgb = rgb a + d (1 - a)`: the old value at a = 1,
  the backdrop at a = 0. Every other quad and mode draws as before; no new pass, texture fetch or backdrop copy.
- The reading [H] is the PS4's masked-layer pass (effect 26 + m, strength 1, through the mask in Da; compositing.md 5.1, 5.2) and knife's `ps_mix`. Two
  weighted cases go beyond it, on purpose, to match the others: mode 8 (knife draws it `NoAlpha`) and flagged mode 10 (effect 36, blend state 0 in the 5.1
  table). Census: 1 held mode-8 statement and 37 held flagged-10 ones, one of them a hidden-colour glow (IMG2229 in `13_00_ARC13_5`); no visible change
  was found at either.
- Not weighted: mode 2 (no script holds it; 13 plain uses) and layers no window holds (the PS4's single pass, compositing.md 2.3).
- Held alpha-ignoring statements in the scripts: 345 (mode 1: 91, 4: 9, 5: 11, 6: 10, 7: 89, 8: 1, 9: 44, 10: 90; 5, 7, 9 without the flag).

Later (branch `v0.1.10-tests`): the driver plays no part. No Synthetic test opens SDL audio, and later full runs of the same tests, with and without the
variable, saw none of these failures (the 4 of 4 was probably other load on the machine). The cause is in the tests: xUnit runs each test on a pool thread,
and the decode its `Task.Run` queued went to that thread's own queue, which the other pool threads take from only when the shared queue is empty (.NET's
`ThreadPoolWorkQueue.Dequeue`), so in a busy run it waited seconds (17 s in one loaded Data run, where the shared queue took 2 s) and the 5 to 60 s bounds
ran out. The game queues these decodes from its own threads, so players never meet it. `ClipCacheLifetimeTests.AFailingDecodeIsNeverCachedAndNeverEscapesAPrefetch`,
which failed on GitHub's macos-15-intel runner (Expected 2, Actual 1), also slept 50 ms where it needed the failed prefetch to have ended (a `Get` that
comes earlier shares the running decode and its error, by design). 5b42b7b runs these tests and two sibling Media tests on a thread of their own and waits up
to 60 s for the state each needs; a3d34e3 lets the two tests that hold trophies.ini go once the step has returned, not after 0.6 s
(`TrophyAppTests.ARecordThatCouldNotBeReadAtStart...` failed in full runs pinned to 2 CPUs); 9682a04 follows the checker's notes. After them: 25 full
Synthetic runs (10 with the dummy driver, 10 without, 5 pinned to 2 CPUs) and 3 full Data runs with it, none failed. Built into another folder, whose test
order differs, Data failed `PortFeaturesAppTests.TheTextWebSocketServesEachLineToAConnectedPageWhenItIsOn` 3 of 3, before these commits and after; not
