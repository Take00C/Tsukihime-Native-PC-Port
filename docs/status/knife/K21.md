# K21: what modern PC visual-novel ports offer, and what this port lacked

Package K21 (label `k21`), run on 2026-10-30 on top of commit 1eb9775 plus the uncommitted K20 package (Tsukihime.exe, the localized-string table `PortText`). Nothing is
committed. Builds in `artifacts/k21` (Release, `-warnaserror`, 0 warnings), temporary profiles under `scratch/k21/` and the test runner's temp folder, every game run hidden and
muted (`--hidden --mute`, `SDL_AUDIO_DRIVER=dummy`) on its own `--save-dir`, the screenshots of the tests in temp folders (never the user's Pictures folder), the copied texts in
files (never the desktop clipboard). No window was shown. `artifacts/play*`, `artifacts/dist`, the user's `%APPDATA%\Tsuki`, the real desktop, Start menu and clipboard, and the
game folder (read-only) were not touched. No knife file was translated (`ConfigScreen.cs`, which this package edits, carries the MPL header since K5a; `docs/THIRD_PARTY.md` is
unchanged). The three `PortText` entries K20 left for this package (`ScreenshotSaved`, `ScreenshotFailed`, `TextCopied`) are used as they were.

## 1. The audit: what PC visual-novel ports commonly offer

Checked against the Steam ports of the same era (the 2020s TYPE-MOON / Aniplex, Spike Chunsoft, Nitroplus and Key ports and the KiriKiri Z / Ren'Py defaults). **present** = the
port had it before K21, **added now** = this package, **not planned** = with the reason, **not done** = asked as a stretch goal and left.

## 2. Screenshot key (F12, Print Screen)

* `EventPump` turns an F12 or Print Screen key-down (not a repeat) into `PlatformEventKind.ScreenshotRequested` (`IsScreenshotHotkey`; SDL synthesises the key-down of Print
  Screen on Windows, which only reports its key-up). `PushScreenshotHotkey` and `PushCloseRequest` queue the real SDL events for the tests and the scripts. `PcInput` no longer
  counts F12 / Print Screen as "some key" (`PcKey.Other`), so a screenshot of PRESS ANY KEY does not also press it.
* `GameApp.RequestScreenshot`: the request marks the next fresh frame and hides the toast (`UiRoot.HideToast`) until it is captured; `RenderCore` reads the window's back
  buffer right after `Present` and before the swap (`GpuCompositor.ReadWindow`: the letterboxed picture at the window's pixel size, rows flipped top-down, alpha 255) and hands
  the pixels to `ScreenshotWriter.Save`, which encodes and writes the PNG on the thread pool (`PngWriter`, zlib fastest) and reports through a queue the loop drains: the toast
  `ScreenshotSaved` / `ScreenshotFailed` (`PortText`, four languages, the file name as `{0}`) and a log line. Only the `glReadPixels` (a few ms at 1440p) stays on the GL thread.
  A repeated frame on a monitor faster than 60 Hz never captures (the capture waits for a fresh frame), so a toast still on show is never in the picture.
* Files: `%USERPROFILE%\Pictures\Tsukihime\Tsukihime_yyyy-MM-dd_HH-mm-ss.png`, `-2`, `-3`, ... within one second or when a file of that name exists (never overwritten);
  `--screenshot-dir <dir>` for the verification runs. The end of the run waits for the writes in flight (10 s at most, logged otherwise).
* `UiToast` (new): one line in a rounded box of the pill palette at the top right (x right-aligned at 1880, y 112..164, under the mode panel), fade-in 8 frames, hold 150,
  fade-out 24 (3 s); `UiRoot.ShowToast`, `Toast`, `HideToast`; drawn after everything else. The language's own glyph pages draw it (the ja / zc / zt pages have the Latin letters
  and digits of the file name; `scratch/k21/ui_final/ui_toast_{ja,zc,zt}_keyboard.png` read).
* Script verb `screenshot`, log lines `screenshot requested (F12|Print Screen|script)`, `screenshot: writing <path> (W x H)`, `screenshot saved: <path> (W x H)` / `screenshot failed`.
  The state line (`log` verb) carries `toast "<text>" a <alpha>`.
* `InputMapper.Bindings` and the launcher's `KeyTable` gain the row "F12 / Print Screen" (the Controls and Help pages show it; `GameLauncherTests` ties the two lists). README:
  the input table, the "PC extras" bullet.

## 3. Mute in Background (Config > Sound)

* `AudioMixer.MasterGainTarget` (any thread) and `MasterGain`: the audio thread multiplies the whole mix after the voices and glides towards the target one step per frame over
  `MasterFadeFrames` = 24000 (half a second), landing on the target exactly; at 1 with nothing to do the period is left alone. The voices' gains and the engine's volume bytes
  are untouched, so the fade never fights the config volumes or the movie volume (the movies mix through the same mixer).
* `GameApp.OnFocus` on `FocusLost` / `FocusGained`: with the switch on the target goes to 0 and back to 1 (`audio: fading out (the window is in the background)` /
  `audio: fading in (the window has the focus)`); switching it off while unfocused restores 1 at once (`PortSettings.Changed`). Script verbs `blur` / `focus` (a hidden window
  never has the focus); the state line carries `master gain <now> -> <target>`.
* The row: `CtlKind.BackgroundMute` (Off / On pills) inside the Sound Settings box: the box's sheet (1432 x 328) is cut below its last slider (sheet row 300), a flat slice (rows
  272..300) is stretched into a 64 px band, the box's bottom edge, the Voice Settings box, the two voice radio pairs, the character rows, their numbers, faces and names move down
  by 64 (`SoundBandHeight`, public for the tests), the tab scrolls 64 px more. The grid: sliders, the mute row, the voice rows. Heading at the sheet's label x: ja
  バックグラウンドで消音, en Mute in Background, zc 后台静音, zt 背景靜音; pills オフ / オン, Off / On, 关 / 开, 關 / 開.
* Stored in `settings.ini` as `mute_in_background=on|off` (`AppSettingsData.MuteInBackground`, the launcher keeps the key when it rewrites the file); `PortSettings`
  (`IUiPortSettings`) reads it at start, saves a change at once and raises `Changed`; `AppServices.Port` hands it to the UI, `PreviewPortSettings` to the previews and the tests.

## 4. Close confirmation

* `AppRuntime.RequestClose()`: the window's `QuitRequested` (close button, Alt+F4, the OS) opens `ConfirmDialog(TitleScreen.QuitMessage = ui_text 236, noFirst: true, ...)`,
  the K18 dialog of the title's EXIT, over whatever is on the screen (the title, the story, a menu); Yes calls `Services.RequestQuit()` and sets `CloseConfirmed`, No returns.
  While that question is already up and unanswered, ours or the title's own (`Ui.Top is ConfirmDialog` whose `MessageId` is 236), a second request quits at once. The story
  stands still under the dialog (the usual overlay rule) and the Enter that answers it does not turn the page.
* `GameApp.Loop`: `close requested: asking the quit question` / `close requested again: quitting`; the stop reason `quit requested (the window's close, confirmed)` (the title's
  EXIT keeps `quit requested (EXIT on the title)`). The tail of the loop is unchanged: `SaveWindowSize`, `Commit` (system data through the atomic write; no slot), the summary.
  Script verb `close` pushes the real SDL close event through the pump.
* The verification scripts' own `quit` verb and `--exit-after` still end the run at once (they are not the window's close).

## 5. Copy Text to Clipboard (Config > System)

* `TextCopier.Step(host)` after every step: a message whose text object or length changed since the last step is turned into plain text (`Markup.PlainText(bytes, lang,
  RubyRendering.Drop, icons: false)`: codes gone, ruby readings gone, `^` joined with a space in English and with nothing in ja / zc / zt, where it breaks mid-word) and copied
  once; an `_MSAD` (`@n`) continuation copies only the part that was added (the plain text's new tail); a choice list that opens copies its lines one per line (the number prefix
  as shown); never the same text twice in a row. While the switch is off the copier only follows what is on show, so turning it on copies the next message, not the current page
  again. A host rebuilt for a language change resets it.
* Sinks: `SdlClipboardSink` (`Tsuki.Platform.Clipboard.SetText` = `SDL_SetClipboardText`) in the game; `FileClipboardSink` (`--clipboard-file <file>`: each text followed by a
  `---` line) in the hidden verification runs, which never touch the desktop clipboard. Log lines `clipboard: message|choice, N chars`, the state line `copies N`.
* The toast `TextCopied` shows once per run at the first copy (a toast per message would be in the way of reading); the log says `clipboard: the first text of the run was copied
  (toast shown)`.
* The row: `CtlKind.CopyText` (Off / On pills) in the band at the bottom of the System tab, after K19's Display Mode and Window Size rows; heading ja テキストをコピー, en
  Copy Text to^Clipboard (two lines, as the sheet's long labels), zc 复制文本到剪贴板, zt 複製文字 (the zt glyph pages have no 簿 of 剪貼簿: the first render showed the word cut
  after 剪貼, `scratch/k21/ui_final/contact_k21.png`, so the shorter word). `settings.ini` `copy_text=on|off`.

## 6. Text Window Opacity (Config > System)

* **Finding.** The PS4 config block has a window-opacity field: config +0x10, u16, boot value 255 (textbox.md 6 and 7: the HUD draws windows 0..2, the dark 1920 x 1080
  overlays of DISP_PARTS 11 / 12 / 13, at `opacity / 255 x window fade`; the speech bubbles 3..55 at a fixed 0.784), and `MessageWindow.WindowFor(w, Config.Hud10, ...)` already
  applies it; the PS4 config **screen** has no row for it (adv_state.md 9.3: "window opacity ... not on the PS4 screen"). So the port adds the row and nothing else: the engine
  is untouched, the value lives in the config block of `save.dat` as the PS4 meant it, Recommended Settings puts it back to 255, and a PS4 save imported by the launcher brings
  255. The text, the name plate and the bubbles are never touched by it (the PS4's own rule).
* `CtlKind.Opacity`: a slider the port draws in the pill palette (a 400 px track with the five step dots of the PS4's sliders, the part up to the knob filled, a knob of the
  pill's height, the value "100%" to the right). `ConfigScreen.WindowOpacityPercent` 0..100 <-> `Hud10` 0..255 (every 5 % step round-trips: 95 % = 242, 5 % = 13). Left / Right
  (or a d-pad) step 5 % without a decide held (the slider is alone in its row); a click lands the knob under the pointer (to the nearest 5 %), a drag follows it; decide alone does
  nothing, as on the PS4's sliders; every change is `ConfigChanged(Setting)` + the commit when the screen closes. Heading ja ウィンドウの不透明度, en Text Window^Opacity, zc
  文本框不透明度, zt 文字框不透明度.
* The band: `SystemBandRows()` = Display Mode and Window Size (a game with a window, K19), Copy Text to Clipboard (a game with port settings), Text Window Opacity (always);
  `BandFor(n)` = 40 + 56 n + 8 (K19's 160 for its two rows, 272 for the four; the System tab scrolls 750 + band). The two-line English headings are drawn at 0.36 instead of 0.4
  so the lines of neighbouring rows stay apart. `UiPreview` scenes `config-port` (the band with the clipboard row On and the cursor on the slider), `config-port-half` (50 %),
  `config-sound-port` (the Sound tab with Mute in Background On under the cursor) and `toast` (the mode panel with the screenshot toast) for `ui-shot` and the real-data screen theories.

## 7. Key rebinding (the stretch goal): not done

What it needs, for the package that does it: a binding table in `settings.ini` (`key.<action>=<key>[,<key>]` per `PromptAction`, read once at start), `InputMapper` built from
that table instead of its literal key tests (the `KeySet` bits stay; the `PcKey` enum needs the rest of the keyboard and `PcInput.ReadKeys` the scancode of every `PcKey`), the
conflict check (one key, one action, except the menu-only letter aliases), Reset to defaults, the launcher's Controls page turned from a table into an editor (a "press a key"
capture per row in WPF, written through `AppSettings.Update`), and the guide prompts (`PromptBindings.KeysOf`) reading the same table so the key caps follow. The pieces 1..5
of this package took the budget; nothing of this was started, so nothing is half there.

## 11. Open issues

1. Not tried by hand (nobody at the keyboard, no window shown): F12 and Print Screen from a real keyboard (the pump path is tested with the real SDL event pushed; Print Screen's
   synthesised key-down is SDL's documented Windows behaviour), the toast over a real story picture, the fade on a real audio device (the mixer's arithmetic is tested; the hidden
   runs pull the mixer without a device), Alt+F4 from the window manager (the pushed close request is the same SDL event), and `SDL_SetClipboardText` on the real clipboard (the
   hidden runs and the tests write to a file so the user's clipboard is never touched; the call is one line).
2. Print Screen also belongs to Windows (the clipboard copy, or Snipping Tool when "Use the Print screen key to open screen capture" is on): both happen then. F12 is the clean key.
3. The screenshot is the presented picture at the window's size, letterbox bars included (black). A 1920 x 1080 capture of the canvas regardless of the window would be the
   compositor frame (`--shot-dir`'s path); not asked.
4. Mute in Background fades the mixer, not the movie decoder: a movie keeps playing silently in the background, as auto mode keeps reading (the "pause when minimised" row of the audit).
5. The clipboard copies the whole message once when it starts, before it is revealed; a text hooker that expects the text letter by letter will see it early. The English joiner
   for `^` is a space, the Asian one nothing; a `^` between two Latin words in a Japanese message would be joined without a space.
6. The opacity slider's steps are 5 % (21 values); the byte could hold 256. The slider is the port's own look (the PS4's slider sprites are the knob only, the track is in the page
   sheet, which the band does not have).
7. Key rebinding (section 7) is not done.
