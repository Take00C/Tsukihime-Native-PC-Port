# K12: the mouse (scroll bars, sliders, guide words, story gestures) and the config text samples

Package K12, run on 2026-10-26. Trigger: "the scroll bar doesn't work if I click it, I have to use the scroll wheel". Owner of `src/Tsuki.Ui`, the mouse part of
`src/Tsuki.Platform/Input` and the App input wiring. Nothing is committed. Every run used hidden windows, `--mute` and `SDL_AUDIO_DRIVER=dummy`, the user's
`%APPDATA%\Tsuki`, `artifacts/play` and `artifacts/play2` were not touched (`--save-dir scratch/K12/...`), builds went to `artifacts/K12` at below-normal priority.

## 1. What works with the mouse, per screen

Pointer positions are now exact canvas pixels (see section 3), so a scroll thumb or a knob follows the pointer to the pixel, not in 3 x 2.4 px steps.

| screen | mouse |
|---|---|
| **every list** (config tabs incl. Controls, save / load, backlog, CG grid, music list, flowchart) | **scroll bar**: drag the thumb (it keeps hold wherever the pointer goes), click the track above / below it for a page (repeats after 24 frames every 6 while held, stops when the thumb reaches the pointer), the thumb lights while hovered (half strength) and fully while held (the sheet DISP_PARTS 15 holds the grey thumb at x 48 and the lit one at x 128). The wheel and Page Up / Down work as before. Page sizes: config 758 px, save list 4 slots, backlog 5 pages, CG grid 5 rows, music list 13 rows, flowchart 840 px |
| config | sliders: click a step dot (snaps within 10 px of one of the five dots) or anywhere on the line (the knob jumps under the pointer), click the knob to grab it without a jump, drag it (it follows off the row and past the ends; the two auto-mode times keep their 50 ms steps); - / + repeat while held; tabs, Recommended Settings, radios, check boxes, mute, test, language buttons, the Controls tab's four prompt pills: click. a pointer that moves onto the page, or clicks on it, takes the focus back from the system menu's tabs (before, the page ignored the mouse while the tabs had the focus) |
| system menu, title, dialogs (Yes / No), mode panel | unchanged (they already hovered and clicked); right click = back |
| save / load | hover selects, a click opens the slot (the confirm dialog is the second step), scroll bar; **guide words are clickable** (below) |
| button guide line (every screen that has one) | click **Back** = cancel, **Confirm** = decide on the item under the cursor, **Delete Data** (save list) = delete, the **shoulder pair** (Switch Page, Switch Picture): left half = L1, right half = R1. Move Cursor / Scroll swallow the click. The rectangles are recorded while drawing (`UiPainter.GuideHits`) and `UiRoot` turns the click into the pad action |
| backlog | wheel, scroll bar, click a message (voice replay or the jump dialog), right click / Back closes |
| gallery hub, CG grid, music player, movies, endings | hover and click as before; CG and music scroll bars; music: the volume slider is **dragged** (click sets it, drag follows the pointer along the line and past its ends); play / pause / stop / repeat / previous / next and the track rows: click |
| CG viewer | click = next picture, click in the left quarter = previous (a click that dragged the picture does not count), drag = pan, wheel = zoom, right click closes; the 2-second guide's shoulder pair is clickable |
| flowchart (gallery and in game) | scroll bar; **drag the chart to pan it** (16 px of travel starts a pan, 1:1, clamped); a click on a node (button released over the node it went down on, no pan in between) selects and presses it; hover selects as before |
| story | left click advances, right click opens the system menu, wheel up opens the backlog, wheel down advances, **wheel button toggles skip**, **pointer at the top edge (12 units) opens the control panel** (once; it re-arms when the pointer leaves the edge), **pointer at the bottom edge (12 units) hides the message window** while it stays there (a click there does not advance), **a drag from the middle of the screen (x 121..519, y 125..383 of 640 x 448) 45 units to the right fast-forwards, to the left rewinds** while the button stays down; a click on empty space while a choice list waits does **not** pick the highlighted line (hover highlights, a click on a line picks it) |

These are the mouse rows of the PS4's own Controls page (config > Controls > Mouse Controls); the last three are knife `touch.rs` rules (edge 25 / 408 units there, a mouse is more exact, hence 12 / 436).

### Controls that still need the keyboard (or a pad)

1. **Copy Data** in the save list (M / SQUARE): the PS4 guide has no word for it either, so there is nothing to click. (Delete Data is clickable.)
2. The story's two-button prompts (`_SELS`, `_SELA`: the "save your progress?" and the QA hint prompt) are not drawn by the host at all (K3 / K6 open issue, not part of
   this package); the choice code accepts the wheel and a click on the cursor, there is no hover.
3. The music player's time slider is display only (nothing seeks, with any device).
4. Quick save F5 / quick load F9, next / previous scene N / B, replay voice V, auto A have mouse routes through the control panel (top edge) but no direct mouse gesture.

## 2. The config text speed samples (item 3)

PS4 function 0x40C30 (knife `sub_2B460`) read from the eboot with `tools/eboot/disasm.py`: for k = 0, 1 it calls `Text_Layout(0x3A + k, ui_text 138 + k, width 200, height 20, spacing 0, leading 0, flags 0, colour 0xFFFF; sx 0.74, sy 0.9176)`, draws the block twice (flags 0x1020 then 0x20) at x 252.333 and y 126.93 / 201.19 (640 x 448 units) with the typing head / tail words, and sets one clip, `(135.667, 68.444, 603, 424.356)` units = the scroll view (x 407..1809, y 165..1023 px). **No per-sample clip and no language branch.** The old code used width 300, height 60, leading 9 and sy 0.9209.
The art box behind the samples ends at x 1267 (measured on the System sheet), the value box starts at 1298.

Ink right edge of the samples at the PS4's own size (px, from `UiText.InkSpan`; box right edge 1268):

| language | sample 1 | sample 2 |
|---|---|---|
| ja | 1257 (fits) | 1257 (fits) |
| en | 1166 | **1325** (57 px over the box, over "15 ms") |
| zc, zt | 1158 | **1307** |

At 0.9 (knife: sub_A7790 scales every English text slot by 0.9) the English second sample ends at 1267.8, on the box's right edge, so the box was drawn for it. The fix, `ConfigScreen.SampleScale`:
scale = min(English ? 0.9 : 1, (1264 - 757) / widest ink at scale 1), both glyph scales and both samples of a language take it, and the text is lowered by half of what it lost so it stays centred in the box.
Result: ja 1.0 (unchanged), en 0.893, zc / zt 0.922; every sample ends at or before 1264 (`TheTextSpeedSamplesEndInsideTheirBoxInEveryLanguage`, four languages). Read as PNGs (`scratch/K12/s2/ui_config-system_{en,ja,zc,zt}.png`): the English "Previously read text." ends inside the box with a margin, "First-time text." well inside, Chinese ends inside, Japanese as before.
No PS4 capture exists: the eboot call has no English branch, so whether the PS4 itself overlaps in English (our layout is the engine's, bit-exact) or the 0.9 lives somewhere we do not see is open; the 0.9 / fit rule is a choice that follows the Switch build and the box.

## 3. Plumbing

* `PointerState` (Engine contracts) and `PointerSample` (Platform) gained optional `CanvasX`, `CanvasY` (NaN = unknown, so every existing constructor call compiles). `PcInput` fills them from `Viewport.ToCanvas`; `InputScript.PointerAt` keeps the exact script pixels; `UiInput.From` uses them (`PointerX/Y`, `PointerMoved` at 1 px) and gained `PointerReleased`; `UiInput.PointerFrame(...)` builds frames with exact pixels, held / pressed buttons and wheel for tests.
* `InputMapper`: the wheel button (middle, held) maps to `ShellActions.SkipToggle` (an edge, once per press); `Bindings` lists the new mouse rows.
* Verification script verbs (`InputScript`): `drag=x0,y0,x1,y1[,steps]` (left button down at the start, straight line, up one step after the end) and `mclick=x,y`.
* `UiScrollBar` (new, `Framework/UiScrollBar.cs`): grab zone x 1831..1879, y 99..995, thumb grab 276 px of the 288 px sprite, `Step(input, fraction, travel, enabled)` returns `ScrollBarUse(Consumed, Fraction?, Page)`; `UiWidgets.ScrollBar(..., bar)` draws the hover / held thumb.
* `UiPainter.GuideHits`, `GuideHit`, `GuideAction`; `UiRoot.ApplyGuideClick`.
* `SideFocus`: the pointer moving onto the page (x >= 372) or clicking there leaves the system menu's tab focus.
* `GalleryPanel.StepPointer` (new virtual) is how the CG and music panels take the scroll bar and the volume drag before the hub reads the pointer.
* `AppRuntime`: top / bottom edge, gesture, misclick guard on choice lists, `CanvasY` for the choice rows.

## 6. Open issues

1. Nothing was run with a real mouse on a desktop (hidden windows only, as the rules say). The path SDL mouse state -> `Viewport.ToCanvas` -> `PointerState` is unit tested and the same fields were driven by script in the real app, but a first session with the physical mouse (drag a thumb, the top / bottom edges in windowed and fullscreen) is the next check. The bottom edge hides the window as soon as the pointer rests there, as the PS4's page says; a user who parks the pointer at the bottom of a windowed game sees no message window until it moves up.
2. The story gestures follow the PS4 page, not a decompiled handler: a drag still starts with the click that advances the text (the engine advances on press), there is no flick / inertia and no drag arrow overlay (knife `touch.rs`).
3. The flowchart pan has no inertia (knife keeps the drag speed for a flick); the CG grid and music list cannot be panned by dragging the content, only by their bar and the wheel.
4. A click on a guide word reaches the top screen as Cancel or Decide, so with a dialog open, Back answers No and Confirm answers the highlighted button. The words are recorded from the last drawn frame (one frame old).
5. The sample scale for English (0.893) is a fit, not a measured PS4 value (section 2).
6. Copy Data and the two-button story prompts: section 1.
