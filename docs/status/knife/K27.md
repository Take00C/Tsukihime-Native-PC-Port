# K27: review and final test of K24, K25, K26, K28 and K29 (screenshot key, other dumps, publishing audit, personal build, setup guide)

Package K27 (label `k27`), run on 2026-10-30 on top of commit f74a533 plus the uncommitted work of K24 (F12 only, the small toast, Screenshot Notice), K25 (other
players' dumps), K26 (`docs/PUBLISHING.md`), K28 (title spacing, the opt-in personal build) and K29 (the player's setup guide). Nothing is committed. Builds in
`artifacts/k27` (Debug and Release, `-warnaserror`, `-m:4`) and `artifacts/k27pub` (the publish), every game run hidden and muted (`--hidden --mute`,
`SDL_AUDIO_DRIVER=dummy`, BelowNormal priority) on its own `--save-dir` under `scratch/k27/app/` with `--screenshot-dir` under it (never the user's Pictures folder),
the launcher only in its offscreen `--render` mode on temp `--data` profiles. No window was shown. The game folder and the update folder beside it were only read; the
other layouts are directory junctions under `scratch/k27/layouts/` (`cmd /c mklink /J`, plain reparse points). `artifacts/play*`, `artifacts/dist`, the user's
`%APPDATA%\Tsuki`, desktop, Start menu and clipboard were not touched. No PowerShell with Add-Type, DllImport, reflection loading or encoded commands; the pictures were
measured with Pillow from `.venv` and read.

## 5. Observations left as they are (not bugs)

1. The backport eboot (the user's update folder) is a known build whose tables are byte-identical to the verified one, yet it is located by content on every start (0.4..0.7 s)
   because only `KnownBuilds.Verified` reads at the documented addresses. K25 decided this; the log says so. Reading known builds at the documented addresses would save
   the half second but needs a per-build statement that the layout is the same.
2. `BuildMatch.Verified` covers every known eboot (K25 open issue 2); the launcher's `IsVerifiedBuild` tells the verified one apart by the start of its name string. It
   works (the split renders say "not the verified build"), but a third enum value would be sturdier than a string prefix.
3. On the split layout the Ready check's Game folder row is a check mark (a known build) while the status line says "Ready, but not the verified build": consistent with
   K25's rule (the warning with a Fix link is for an eboot the port does not know), but a player sees two different words for the same copy.
4. `GameFolderSource.Open(string)` on a split layout hashes the base eboot once in `BaseIsCurrent` and the winning eboot once in `Identify` (two 12.7 MB reads, ~30 ms
   each); the launcher's `Inspect` does the same. Harmless.
5. The F12 run with K24's recipe shows the prologue's first caption at step 760 on a fresh profile (K24's own run, on a profile that had seen the prologue, showed the title
   with the quit dialog); the point of the recipe (a PNG and the small toast) holds either way.
6. `docs/PUBLISHING.md` names `Tsuki.Launcher.csproj` lines 52-53 for the conditional licence copies; they are 53-54 since K28's import. Its other claims hold (finding 9).
7. The Korean tile of the launcher (`LauncherModel.LanguageName(Language.Ko)` = 한국어) exists for completeness; nothing offers it, as the data has no Korean text.
