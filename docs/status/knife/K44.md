# K44: issue #9, flowchart scenes that never light ("Stay in the Classroom")

Package K44, run on 2026-11-02 on `d592a29` (v0.1.4), beside K45 (issue #10, another agent, same tree). Nothing is committed. Builds in `artifacts/wf_flow`
(Debug, Release CLI, `-warnaserror`, 0 warnings); for the before / after runs, v0.1.4 itself (`git archive HEAD`, only the new sweep files copied in) in
`artifacts/wf_flow_head`. The sweeps are headless CLI runs; the real app ran twice, hidden and muted with a temporary `--save-dir`. The game folder was only
read, `%APPDATA%\Tsuki` was not touched; BelowNormal priority.

The report: "Even though I took the 'Stay in the classroom' option, it still doesn't unlock in the flowchart gallery and isn't selectable." Screenshot:
the cursor on a black node with the card "Current Scene / Stay in the Classroom", a second black node lower in the chapter.

## 1. What the PS4 does

| | PS4 (eboot) |
|---|---|
| a node shows | once its scene is done (`_RDED`) or its link edge was seen; its picture only when done (0x25950: the mosaic sprite's visible bit is cleared otherwise) |
| who can pick it | gallery: done nodes only. In game: nodes reached in this playthrough, outside the prologue's column group, done or not |
| "Stay in the Classroom" (node 68) | `01_00_ARC01_2` (node 51) choice point 2, line 1 -> `_JUMP(305)` = `01_00_ARC01_2_2`. That script has no `_RDED`: it jumps into the cafeteria scene `01_00_ARC01_2_1` (node 67) at `LBL_004`, whose shared tail ends `_RDED(67); _RDED(68); _RDED(311)`. The jump code 0xB9460 treats 68 -> 67 as a special pair: no edge, F110 stays 68, so `_RDED(68)` completes 68 |

**The reporter's first state is the PS4's own behaviour**: while you are inside a scene its box is black; the in-game chart lets you select it (that is
the "Current Scene" card), the gallery does not. It lights when the scene ends. For players: *a scene's flowchart box stays black until the scene ends,
as on the PS4; before v0.1.5 some scenes stayed black even after they ended, which is fixed.*

## 2. What was wrong (v0.1.0 .. v0.1.4)

- The `_JUMP` marks knew only the plain edge table, none of 0xB9460's 69 special cases: every jump set F110 to the target. So 22 scenes never
  completed: those that end in another scene's shared tail (68 "Stay in the Classroom", 57 "Someone Else We Played With", most likely the screenshot's
  second black node, 105, 108, 127, 152, 202, 205, 250, 258, 311, 446, 447) and those reached through hidden nodes (the prologue's 485 / 486, 270, 275,
  276, 279, 280, 281, 483). The 33 hidden nodes (498..530, the bad-end branch markers) never lit, nor their edges.
- `_SELD` never marked its choice edges (0xB8620: when a list opens, all its options' edges), so options not taken never showed.
- The cursor of the last decision (word 0x17506A6), which picks the hidden node of five jumps, did not exist.
- Minor: the grey connector of a done node whose own edge was unseen was not drawn (0x25F9E reads the node's drawn bit).

## 4. Saves of v0.1.0 .. v0.1.4

On start, once (a profile that started node 1 without node 485 done; about a second, it reads every script), `FlowRepair` adds what the save proves
the PS4 would have marked, and writes it to save.dat at once:

- the edges of every choice point taken (`choice_taken`), without the two state-dependent bits of points 72 / 73;
- the prologue (node 1 started): nodes 485, 486, hidden 528 / 529, their edges;
- every jump an old edge bit proves: the rest of its PS4 marks when they do not depend on the playthrough (the extra edges of 355 -> 20, 136 -> 137, 213 -> 215, ...);
- a scene ending in a shared tail, with the marks of the tail's exit jump (68 -> 66: edge 634): done when the tail's last marker was read and the scene is
  the only one started of all that can reach that marker (the tail's own scene, every scene whose jumps keep it current on the way, 205 -> 105 -> 204
  included), or when a save slot's playthrough reached the scene and the exit's target but none of the other scenes that lead there.

And on every load: a slot that v0.1.4 saved inside such a tail holds F110 = the tail's own node; it gets the scene it came from back (when its
playthrough reached exactly one of them), so the tail's `_RDED` completes it.

Not repaired, because the save cannot tell: a tail read both ways with no slot to prove the way, and the hidden-node jumps that depend on route bits or the
last pick. Those light the next time that part is played to its end.

Check (`--sessions` with v0.1.4, then `--repair-check` with the fix, on the same 107 sessions): **5,882 bits added, all 5,882 also set by the fix's own
session, 0 that the PS4 would not have set**; of the 575 scene completions v0.1.4 missed (summed over the sessions) the repair restores 449, the rest are
hidden-node paths and tails read both ways. The check only has finished sessions; scenes started and left are covered by the tests (section 7).

## 7. Review

Three reviewers (PS4, save safety, integration) confirmed the root cause and the marks; their findings were all in the old-save repair. Fixed in the same tree
(`artifacts/wf_fix2`); the repair was rebuilt as a walk over the scripts (next statement, both ways of an `_IF*`, `_GOTO`, jumps that keep F110).

| finding | verdict | fix and test |
|---|---|---|
