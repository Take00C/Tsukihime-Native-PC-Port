# K2: the stage (layers, tweens, motions, quakes, grade keys, transitions)

Owner: package K2. Spec: [`docs/formats/layers.md`](../../formats/layers.md), [`docs/formats/quake.md`](../../formats/quake.md),
[`docs/formats/compositing.md`](../../formats/compositing.md) 5-7, 9 (the verified PS4 behaviour wins over knife). Code: `src/Tsuki.Engine/Stage/`.
Oracles: `tools/tsuki/misc_layer_state_and_motions*.py`, `tools/tsuki/quake.py`, `tools/tsuki/compose.py`, and the engine itself under
unicorn (`tests/Tsuki.Tests.Data/Stage/engine_stage.py`).

Status: **done**, with the open issues at the end. The 40 script layers, the commit / FADS machine, the tweens, STMA motions, quake / shake / swing, the
screen shock, SHOK, the colour-grade keys and the transitions are built, and the stage turns itself into a `DisplayList` each frame. Verified against the
engine's own code (random scenarios and the traced paths of the golden slice), against the Python oracles (vectors) and against the renderer's transition
commands.

## How the interpreter drives it (package K3 does exactly this today)

```csharp
var stage = new StageRuntime(tables.Pictures, tables.Motions, rng)        // tables: IEbootTables (GameEbootTables / GoldenEbootTables)
{
    HazeTable = tables.Haze,                                              // only if STRA is to be drawn
    Layouts   = new GamePictureLayouts(gameFolderSource),                 // null: the layers produce no quads (headless)
    Language  = 0..3,                                                     // 0 ja, 1 en, 2 zc, 3 zt (picture language bands)
    MotionWaitConfig = config.ConstantA5,
};
stage.Execute(statement);            // every layer statement (returns false for a statement that is not the stage's)
stage.Update(arg);                   // once per 60 Hz step; arg = frames of the step (FramesPerUpdate scales it)
StageDrawInfo info = stage.Draw(list);   // appends the scene to the DisplayList
```

* Set before `Update`: `ScanMode` (the interpreter's scan flag), `SkipActive` (a skip in progress finishes tweens and transitions at once), `MenuFraction` (1.0 while the
  system menu covers the screen: the layer part of the update is skipped, as on the PS4), `FramesPerUpdate`.
* After `Execute`: `MotionWaitRequested` (the `_STMA` wait mode asks the interpreter to wait; the interpreter clears it), `SceneDirty` (the scene block changed),
  `CommitPending`.
* `Draw` returns `StageDrawInfo(RuleTexture, RuleProgress, LayersDrawn)`. When `RuleTexture` is not null (a type-2 `_FADS` rule wipe) the executor must give that
  texture the transition parameters of `TransitionParams.ForRule(RuleProgress)` this frame (the engine sets them every frame, 0xD73B0).
* `TextureRef.D` of a picture tile is a **grade key**: `GradeKeys.Resolve(key)` gives the `ColourGrade` (STEC mode, SNX2, SNX3, colour) that the texture cache applies when it
  builds the tile texture (0xD36F0, `stec_apply_bgra`). Key 0 = no grade.
* `StageRuntime.Scene` is the `SceneState` block the history ring (K4) saves and restores; `Drawn` / `Committed` are the records the rebuild-from-committed reads.

Fixes found by these comparisons (each is an erratum in layers.md or quake.md): STCH and SCH2 both clear a layer's shake slots (0x4A770 at 0x81A9C / 0x81ABB, quake.md 3.5);
a masked layer takes the sum of its own and its mask layer's shake terms (second draw path 0x49A60, quake.md 5); the libc `sinf` is not `MathF.Sin`; the commit writes B
except zoom, the B to A move runs after the layer loop and only moves texture parameters when a texture is involved; STGS divides by 255 (it does not multiply by
a rounded 1/255); STZ4's delta is `-((x1*0.001f)+(x0*-0.001f))`; the empty-name and `src < 0` STCH paths clear B's motion record too; STPV writes both anchors; the
crop rectangle is a window in 1920 x 1080 screen pixels, not in picture pixels; a masked layer below its mask layer in z order is never drawn (the engine scans the slots after the window layer
only, 0x5A8E1), found when the scene draw joined the random scenarios, as were the group-path rules (a window, rule-fade or mask-source layer is drawn even at alpha 0 or behind an empty window), the draw-time advance of the STNS
counter and the missing draw call of pictures without live tiles (layers.md errata block, "Errata for layers.md itself").

## PS4 against the Switch build (knife)

| topic | PS4 (this stage) | knife |
|---|---|---|
| clip window and mask | `crop` is a scissor rectangle in 1920 x 1080 pixels (0x49A60); the layer named by `mask` is the clip parent: it is drawn inside the window layer's pass and shifted by the sum of both shake terms | the same window; the PS4 numbers decide |
| motion loops | code, not data: `loop_point` at text 0xC1C70, run by `TinyX86` | a table (`motion_loops.rs`), 2,027 / 2,027 equal |
| STEC | evaluated LUTs on the CPU at texture build (0xD36F0) | shader parameters; the stage only hands a grade key to the texture cache |
| grade rebuild | when the picture changes (default, knife's rule) or at every commit with `RegradeOnCommit`; the PS4 rule is a hypothesis (open issue 1) | when the picture changes |
| quake / shake | formulas of quake.md with the bit-exact libc `sinf` and `rand()`; no table | formulas, `f32::sin` |
| STRA | state machine 0x86EE0 / 0x588A0 (phase modulo 6000, fade-in / fade-out) and `HazeTable` (558 x 10 f32) | `Haze::params`, same meaning (16 entries differ, knife_tables.md) |

## Open issues

1. **Grade rebuild policy** [H]: when `_STEC` / `_SNX2` / `_SNX3` change on a layer whose picture stays the same, the PS4 may or may not rebuild the graded texture at the next commit.
   The stage regrades only when the picture changes (knife's rule); `RegradeOnCommit = true` regrades at every commit. Needs an engine trace of 0xD8B80 / 0xD6900.
2. **The recolour kernel is not in the texture cache yet.** The stage puts the grade key into `TextureRef.D`; applying `stec_apply_bgra` (compositing.md 9; LUTs of
   `read_stec_tables`, LUT[0] forced to 0; `stec_golden.json`) while a tile texture is built belongs to the renderer.
3. **Not drawn** (the state is modelled and compared with the engine, the quads are not produced): rotated clip windows and the soft clip insets (STCH a16 / a17), per-layer rule fades (`_STTR`),
   the quads of the STNS noise overlay (its frame counter advances like the engine's), the STRA haze pass (a layer with a running STRA is drawn as a plain picture; the executor needs the pass,
   `StageRuntime.Haze(layer)` gives the parameters), and the **group pass** of window / masked / rule-fade layers: the engine draws such a layer offscreen (the layer at alpha 1, the layers masked by it,
   then the layer again as alpha mask, effect 58; 0x5A5E0), the stage emits the quads with the crop rectangle as scissor. The scene draw tests leave layers with a running STRA out of the comparison of the
   layers drawn.
4. **`_FADS` types 18, 20..24 and 68..70** (engine-only screens): the start commands are emitted, the frame draws nothing (the renderer's `FadsCommands` throws for them as well).
5. **SHOK offset on the transition capture quad** is not applied (the captured frame stays still while the layers shake).
6. **Colour tween animation** (0xF830 / 0xF380) and the **rewind word 0x17DB234** (motions run backwards during a rewind) are not modelled; the history ring (K4) restores the committed state instead.
7. The crop ease (+0x150 / +0x154) and the alpha-delta rate (+0x10C) were never seen non-zero in the corpora; they are stored and compared but nothing drives them. The easing ids 12, 13, 16, 17, 21..25,
   28..33 and 36..41 (101 of 42,769 motion keys, none of the retail tweens) are float64 formulas as in the oracle (layers.md 8.5: relative error up to 2.2e-6 against 0xBC460), not bit-exact ports.
8. **Wiring that is not the stage's**: `GameServices.Layouts` is null in `HeadlessRig`, so headless runs draw no quads; the app / explorer should pass `new GamePictureLayouts(source)`.
   The texture cache must resolve `TextureRef.D` (issue 2) and give the rule texture its transition parameters every frame (`StageDrawInfo`).
9. `GamePictureLayouts` returns null for a picture whose file no archive holds (3 sprite variants named by the catalog, e.g. `ARU_M_03_35_N02`) and an empty tile list for 44 files whose
   tiles all have flag 0 (placeholders such as `img2344`, `img5010` and the unused solid colours BLUE, GREEN, ORANGE, YELLOW); the layer then draws nothing, as the engine's texture build would.

## Tools

`python -I tests/Tsuki.Tests.Data/Stage/engine_stage.py <seed> <statements> [--layers N]` prints the scenario and, per step, the engine's changes (scene bytes, drawn / committed
records, z slots, `rand`); `--scenario <file.json>` runs a given list of steps (`s` statement, `u` update, `d` draw) and adds the oracle's frame matrices and the layers the engine
draws. `python tests/Tsuki.Tests.Synthetic/Stage/gen_stage_cases.py` rewrites `StageOracleCases.g.cs` from the Python oracles.
