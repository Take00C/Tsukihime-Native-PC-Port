# K13: the story's two-button prompts (`_SELA` save prompt, `_SELS` yes / no prompt)

Package K13, run on 2026-10-26. Trigger: K12 open issue 6 ("the story's two-button prompts are not drawn by the host at all"): at every chapter start the story waited
on an invisible dialog. Owner of `GameHost.Prompt.cs` / `PromptLayout.cs` (Engine/Game), the UI drawing (`UiStoryPrompt.cs`) and the App wiring. Nothing is committed.
Every run used hidden windows, `--mute` and `SDL_AUDIO_DRIVER=dummy`, below-normal priority; `artifacts/play`, `artifacts/play2` and `%APPDATA%\Tsuki` were not touched
(`--save-dir scratch/K13/...`), builds went to `artifacts/K13`. `Tsuki.Render`, `Tsuki.Data` (source), `Tsuki.Engine/Stage`, `Tsuki.Media`, `GameApp.cs`, `AppArgs.cs` (K11's) were not touched.

## 1. What was wrong

* `_SELA` / `_SELS` opened a choice the host stepped like the list (alpha 0.04 per frame, a 51-frame "decided" phase with a flash), but **nothing drew it**, and a
  click on empty space was the only thing the code could see. The player could not see why the story had stopped.
* **The buttons were swapped.** The host opened the save screen for cursor 0, the eboot does it for cursor 1: button 0 is **No** (left, widget 0xD5), button 1 is **Yes**
  (right, widget 0xD6). `docs/formats/vm_variables.md` 4.5 and knife (`pick_choice`: `ChoiceKind::Save => state = if i == 1 { 5 } ...`) agree; both autoplays answered `1` for "no", which
  with the right numbering would open the save screen and stall every long run.
* The "decided" phase of the list (51 frames) was used for the prompts; the eboot's is 10 frames.

## 2. What the PS4 does (read from the eboot with `tools/eboot/disasm.py`, `.venv`'s capstone)

Full notes in `docs/formats/system_flow.md` 5.7 (new). Short form:

| piece | PS4 |
|---|---|
| setup 0xA5DF0 | phase 0, **cursor -1** (neither button selected), alpha 0, `0x75CD0(1)` (new page), F823 = 0, F1103 = 1; message `ui_text(216)` (SELA) / `ui_text(1446 + F27)` (SELS; retail F27 = 1..9: "Play dubious hint segment #N?") |
| fade | phase 0: alpha += 0.1 dt to 1, then phase 2 (selectable); phase 3: alpha -= 0.1 dt, the choice ends at alpha <= 0 (10 frames). The window pops 1 + 0.05 (1 - a) while opening and 1 - 0.05 (1 - a) while closing after an answer |
| SELA Yes (cursor 1) | phase 4 (fade out) -> 5 (open the save menu 0x16) -> 6 (wait until it is closed) -> 7 -> 3 (ends at once); nothing is stored. No (cursor 0): phase 3 |
| SELS | stores the **cursor** (0 No, 1 Yes) in its target (`_D000` = F0), then phase 3 |
| input | cancel pressed or the pointer's right button voids the frame; the hovered button takes the cursor (SE 2); decide (mask 0) or a left click answers (SE 0) **only when a button is selected** (cursor -1 = `0xFFFF` is above 1); a click beside both buttons is void. Left: cursor > 0 -> cursor - 1, else a *fresh* press gives Yes and a repeat No; right: cursor <= 0 -> cursor + 1, a fresh press on Yes wraps to No; up = No, down = Yes |
| draw 0xA7CD0 / 0xA8250 | `dialog_BG` (child 21, slot 360) over the whole screen at alpha **a** (not 0.75 a), `dialog_win` (child 20, slot 358) centred at **(321, 224)** units scaled by the pop, message block (474 x 220, leading 9, `sx 0.37 s`, `sy 0.46044 s`, draw flags 0x1000 = outline, layout flags 0x100 = centre) at (83.333, 224 - 42.311 s), widgets 0xD5 at (241, 238.52) and 0xD6 at (327, 238.52), cells of `dialog_btn_ja` (child 19): plain No (224, 67) / Yes (224, 0), selected No (0, 202) / Yes (0, 135) |
| hit boxes | widget records 0x8731F0: shorts (-10, -10, 60, 45) added to the widget position, truncated, in 640 x 448 units, ends included: No x 231..301, Yes x 317..387, y 228..283 |

knife's `choice.rs` / `ui.rs draw_choice_dialog` has the same numbers (No at 241, Yes at 327, y 238.52, 0.37 x 0.46044, -42.311, pop 0.05, fade 0.1); where the eboot and knife differ the
eboot won: the window centre x 321, the pop only in phases 0 and 3 (knife also shrinks in 4 / 5), cursor -1 at the start, the left / right wrap rules.

## 3. What the port does now

| | |
|---|---|
| host state machine (`GameHost.Prompt.cs`) | the phases above, `Choose(0 / 1)`, `PromptOpen`, `PromptMessageId`, `PromptScale`, the pointer hover (it selects when the pointer **moves**, comes into the game area or a button goes down: a pointer resting where the dialog appeared selects nothing, so a keyboard player with the mouse in the middle of the screen is not hijacked), SE 2 on a move and SE 0 on the answer, `ChoiceDecided(kind, -1, cursor, cursor)`. Scan mode: `CmdSeld` now also opens nothing in scan mode (the prompts already did through `VarCommands`); a `_SELA` still clears F1118 |
| SELA Yes | the host raises `SavePromptAccepted` after the fade (phase 5) and **waits in phase 6 until `SavePromptScreenClosed()`**; with no listener (every headless runner) it does not wait. `AppRuntime` pushes `SaveLoadScreen(save: true)` over the story and calls `SavePromptScreenClosed()` when that screen has left the stack (Back, or Back after a save: the list stays up after a save, as from the system menu) |
| drawing (`Tsuki.Ui/Framework/UiStoryPrompt.cs`) | `UiStoryPrompt(MessageId, Cursor, Alpha, Scale)` from `IGameServices.StoryPrompt` (default member: null); `UiRoot.Draw` draws it with the PS4's numbers while **no screen is open** (the system menu hides it, the host holds it); the guide line below it is `UiWidgets.GuidePrompt` (index 12, not a PS4 guide: Confirm and Move Cursor from the same words and icons) in the current prompt style (K9: key caps, PS4 icons, Xbox glyphs) |
| mouse | hover and click as above; a click on the guide's **Confirm** word presses decide (`UiRoot.StoryPromptConfirmClicked`, K12's guide rectangles); a click on the dialog does not also advance the text or open anything |
| pad | d-pad and the left stick (the eboot reads only the d-pad bits; the stick is a port addition), south = decide |
| keys | arrows (Left / Right / Up / Down), Enter / Space / Z. The cancel button (X, the pad's east button) does nothing, as on the PS4; Esc, M and the right click are the story's system-menu keys and still open the system menu over the prompt (the shell keys run before the host; the menu hides the dialog and holds the host), and the prompt comes back when it closes |
| autoplay | both runners answer **No** to a SELA (the old `1` is Yes now) and **Yes** to a SELS (QACALL goes to the hint scene): `Tsuki.App` `AutoPlayer` (new script verbs `holdprompt` / `releaseprompt` leave the prompts to a script), `Tsuki.Cli` `AutoPlayer` (`play`, `play --coverage`, `effect-shot`); `FlowExplorer` already treated a SELA as No and a SELS as Yes |

## 6. Open issues

1. **No PS4 capture** of either prompt exists (`docs/status/ps4_captures.md` M04 / M05 are still wanted): every number is from the disassembly and knife. What the eboot does not say: what the three setters at phase 4 (`0x6F450(1)`, `0xEA0D0(1)` store to 0x1202F10 / 0x20773C0, `0x6F460` is a `ret`) do, and whether the PS4's save menu 0x16 closes itself after a save (`0x71C90(0) == 3`): the port's list stays up after a save and Back leaves it.
2. The guide line (Confirm, Move Cursor) is a port addition; the PS4 shows none in the story. Esc and right click open the system menu over the prompt (as over a choice list); the PS4's own input code ignores them.
3. The pointer selects a button only when it moves (the PS4 re-reads the hovered widget every frame). A resting mouse over a button therefore does not fight the keys; the button under it is selected by the first move.
4. Saves made from the prompt's screen have a **black thumbnail** (the chapter start is a black screen with particles: `BeginOverlay` grabs the frame as drawn); their record is the page start before the `_SELA`, so loading it re-enters the chapter start with F1118 = 1 and no prompt (tested).
5. `_SELS` is reachable only through the QACALL / QA hint scene (scene 3100, a debug path), so it was verified at the host (retail script), UI (preview scenes) and runtime (hand-made script) level, not by a played real-app run.
6. Nothing was run with a real mouse or pad (hidden windows, scripted pointer and keys): the hit boxes, the hover rule and the Confirm-word click are unit tested and scripted.
7. `PromptLayout` keeps the hit boxes in whole 640 x 448 units (`PointerState.X / Y`), as the PS4 compares them; the exact canvas pixel (`CanvasX / Y`) is not used.
